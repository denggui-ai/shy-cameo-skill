# 入画 · shy-cameo

用成年人本人或已获同意的照片拍五张故事写真：本人是主角，陪同角色害羞不露脸。

`CLI` = `python3 <本技能目录>/scripts/cli.py`。`WS` = 仓库外持久私有工作区，保存原照与私人记录；未指定时建议 `~/Pictures/shy-cameo/<项目名>/` 并请用户确认。子命令返回 JSON，退出码 2 时按 `status` 处理。

## 什么算开拍

- **算开拍：**“按这套拍”，或对明确开拍提议回答“同意”；无需固定口令或重复确认张数。
- **不算开拍：**确认方案、选择套图列表；安装、开发、发布或讨论中的“继续”。
- **单张重拍：**“重拍第 3 张”表示该张一次新请求，保留旧版。

## 主流程

1. **理解目标。** 沿用角色、地点、衣装和偏好，只问影响画面的缺项；造型或局部修改按所问范围处理。没有想法时读 [开场与选题](references/opening-and-topics.md) 给菜单或推荐；内部分类由技能完成。
2. **写五张分镜。** 读 [写分镜](references/storyboarding.md)，说明身份、衣装、画风、事件和拍法；写清关键道具的使用者、动作、状态与支撑。比较故事作用、姿态、视线、表情和景别；保留用户指定的相似姿态或连续机位。
3. **只准备。** 保存草稿，做可用的 Schema 检查、`CLI scan-names` 与 `CLI check-pose-variety --set-card <草稿路径>` 构图建议检查；无需生图登录。缺环境标待校验，缺素材列待办。用户确认后才记 `user_confirmed`；库内模板先复制。
4. **核对开拍条件。** 按上文判断开拍意图。读 [生成执行](references/generation.md)，运行 `preflight`，核对已确认分镜、角色造型、照片质量与成年、本人或主体同意、发送给图像服务的同意。有效记录沿用；他人照片须事先说明用途并取得单独同意。
5. **登记范围。** 按上文确定本次请求，每套最多五次调用，多套按明确列表合计；失败也可能计次。定妆表须另行要求。说明实际参考及预算丢弃项（超数量上限未传入的参考图）。
6. **执行并记录。** Codex 逐张 `compile-shot → 内置 image_gen → set-record`，原样传入请求；Claude Code 用 `generate-set --authorized-count 5`。Codex 靠流程与事后核对，不能声称脚本硬拦。中断先查 `set-status`。

   **出错处理：**

   - 首张失败或被拒：取消后四张，停止本套。
   - 后续单张失败：不重试，按已有授权处理余下镜头。
   - 超时或无图：保持 `claimed`，核实并登记结果后才决定续拍。
   - 露脸封面比脸分低：给用户比脸，像再继续，不像则改方案另起一套；比脸不可用时说明未做机器比脸。

7. **检查与交付。** 读 [交付与修订](references/delivery-and-revision.md)，逐张目视本人、人体、角色、道具空间关系和摄影目标；比较本套已出图的姿态与故事变化。非用户指定的重复影响整套时，停拍并说明。逐张 `verify`、`frame-check`、`deliver`，保留原图字节；审计、文件完整性、画质与用户接受分别报告。
8. **反馈与选版。** 按用户实际回答 `record-verdict`，缺项只补问。局部修改或重拍保存新卡、新请求和旧版。用户选用才更新版本；方向认可不代替整套接受。

多套或续拍读 [系列与项目](references/series-and-projects.md)。每套用自己的首图串联，即后续图参考首图保持衣装、妆发和影调；拍完停下交付，明确继续后 `project-continue` 登记下一套。`project-status` 只读汇总，`gallery` 生成本地作品页。

## 红线与边界

- 陪同角色不露脸，用体态、服饰或局部互动认人；本人居视觉中心，不靠巨大角色前景补辨识。每套本人 1–2 张清楚正脸，其余用背影、手、越肩、背面剪影或远景与一致衣装认人；不画正面无脸人形。
- 成年人限制只针对身份参考照片，虚构角色可以是孩子；与未成年角色的互动限于陪伴、玩耍等，不出现亲密或暧昧的姿态与情节。角色不露脸属创作设定；版权、国别、作品年代与题材不一概禁用，详见 [权利说明](references/rights-cplus.md)。演员名扫描区分造型来源与角色身份，不冒充法律判断。
- 平台拒绝如实转述，未知原因明说；不改词、隐去意图或换服务重交被拒内容。可提实质不同的替代方案，按实际授权另建请求；再被拒即停。失败、超时或余额不构成重试许可。
- 原始照片、私人日志与凭据不进源码、案例或安装包；不读取或回显 `.env`、API key、账号 token。用户明确要求的本地案例整理仅复制选定生成成片原字节和去除私密信息的说明。本流程不代发帖、操作发布账号、`git push` 或远端发布。
- 超出 Schema 或工具能力时说明限制；程序检查不证明成片效果。只核对本镜头缺少的身形信息，需选图时读 [身形参考](references/body-reference.md)，不自动生图补库。

## 状态与完成

分镜：`unverified` 草稿 → `user_confirmed` 用户确认。角色：`temp_draft` 草稿 → `temp_confirmed` 用户确认；`gold` 为维护者确认的库内模板，均不代替本次拍摄请求。

单张账本：`pending` 未提交 → `claimed` 已编译占用、结果待核 → `generated` 已生成 / `rejected` 被拒 / `failed` 已核实失败；首张失败后的其余张为 `cancelled`。未知结果保留 `claimed`，账本缺失但存在历史产物时停下核对，不重建为未开始。

审计只比较唯一完整请求会话窗口：`pass` 参数与次数核对通过；`unverifiable` 无法审计并说明原因（兼容历史 `unverified`）；`tampered` 不一致，不能记接受。审计不证明账单或视觉效果。

五张均完成检查、交付与用户自检，且 `verdict: accepted` 才算整套完成。`set_generated` 只表示已生成；没有用户自检保持待验收。
