# 入画 · shy-cameo

主角是你，故事里的角色有点害羞。陪同角色不露脸，在主角突出、互动自然的前提下，用足够的体态、服饰或标志性局部让人辨认；不要把害羞默认写成只露一只普通手，也不要靠放大角色抢占前景补辨识度。模型负责理解与对话、产出卡片 JSON；确定性脚本负责守规矩：姓名扫描、参考图预算、害羞设定与构图建议、授权与额度、套图账本、交付标识。

约定：`CLI` = `python3 <本 skill 目录>/scripts/cli.py`；`WS` = 用户指定的仓库外私有 `coshoot-workspace/`，原始自拍与私人记录留在该工作区；用户明确要求整理案例时，可将选定的生成成片原字节复制到开发案例目录，原始自拍不复制，远端发布另按用户指示。每个子命令输出一个 JSON 对象；退出码 2 表示阻断或失败，读 `status` 字段处理。

## 主题与验证范围

按用户选择的角色、服饰和画风准备，不因作品国别、版权年代、超级英雄题材或虚构角色年龄一概拒绝。真人感与动漫感是画风选择，不强制改名原创。三套原创动画主题（阿檀、纸鸢、伞伞）的分镜及兼容记录见 `references/animation-themes.md`；这三组是已测样例，不是许可名单或永久题材边界。角色不露脸是本技能的害羞拍法，不是法律要求。未实测的组合如实标为未验证，不说成禁止。

## 宿主路由

兼容要求：macOS/Linux、Python 3.9+；Codex 原生生图为主，Claude Code 经已登录的 Codex CLI 0.161.0+ 执行。自动触发与画质支持以发布说明的实际验证范围为准。

- **Claude Code**：一套 5 张用 `CLI generate-set ... --authorized-count 5`，第 1 张失败时脚本自动取消其余 4 张。结果未知（超时、没拿到图）时脚本暂停并保持该张 claimed：核对后 set-record，再加 `--resume` 只拍未提交的张。露脸封面拍完若机器比脸分偏低（`set_paused_likeness`，需本地比脸模型，见 references/face-likeness.md），脚本停在第 1 张：先给用户比脸，用户说像再 `--resume` 续拍本套，不像就改方案另起一套。逐张进度写在 stderr，建议后台运行并按进度向用户报告。
- **Codex**：按 `references/backend-codex-native.md` 的“套图”一节，逐张执行 `compile-shot`（先将账本标为 claimed）→ 内置 `image_gen` → `set-record`（登记实际结果）。第 1 张失败后，`compile-shot` 会拒绝编译后面几张；这条路径只能事后核对，不能硬拦。

## 同角色多系列主线

角色项目 → 主题系列 → 五张套图 → 单张版本。五张是一套的单位，不是角色项目的上限。选多套、全部、返回续拍或整理版本时读 `references/series-projects.md`；策划系列、比较重复，或用户要求影视辨识度、经典画面与电影摄影时读 `references/series-creation.md`。已有具体单套需求仍直接走原流程，不强制项目向导。只喜欢某角色时先拍一套；交付后问“要不要接着拍？”并给3个有区别的新系列，用户选中才加进selection，再 `project-continue`，允许自由创意。

项目索引保存在WS/project.json，`CLI project-status --workspace WS`只读汇总现有账本和验收记录；`CLI gallery --workspace WS` 据此写本地作品页 `WS/gallery.html`（只看，选版在对话里说）。索引中的selection记录本次明确套图列表，不是生成授权；全部只覆盖当时选定列表。按所选顺序逐套执行，各套首图独立串联；每拍完一套都停下交付；用户说“继续”后先 `CLI project-continue` 登记再拍下一套（脚本会拦未登记的后续套）；未知结果立即核对。新图不自动替换旧版，生成、交付和接受分别报告。完整规则及格式见series-projects。

## Workflow

先按 `references/routing-and-journey.md` 理解5类能力路由、用户旅程和摄影效果；写卡读 `references/scene-card.md`。用户的明确选择优先，不增加题材白名单或重复授权口令。

1. **理解目标**：从用户原话理解想和谁、去哪里、扮成什么样或经历什么；这是一句开放邀请，不是四项必填表。已有明确需求直接回应，复用照片、衣装及偏好。由技能内部映射play_mode，不向用户展示内部分类；没有想法或问“能拍什么”时给菜单（见dialogue.md，第一句“角色不露脸”人设句保留），点菜单项与直接说等价。缺必填才问，问法见dialogue.md。复合需求保留；真正会改变画面的歧义，用生活化的结果对比问一句。
2. **方案与卡片**：分别说明本人身份与衣装、本人/环境/陪同角色的视觉表现、空间语境和摄影方向。新方案用可选visual明确表达；旧style保留兼容。用分镜展示动作和差异，保存unverified套图。仅文字策划也须把关键道具的可执行关系写进对应镜头：谁使用或持有、手的动作与物件状态，以及必要的承托或作用范围；多人共同使用时交代双方位置和方向。只写影响当前活动的关键关系，普通背景物无需逐一说明。cover/wide/interaction/shy/ending只是账本槽位，不强制第四张遮脸或固定递物节拍。 成套比较每张的故事作用、身体动作、头向视线、表情和景别；运行套图建议检查并处理相关提示。用户有意指定相似姿态或连续机位时按其意图执行，不因建议机械改写。
3. **只准备分支**：本地Schema检查与姓名扫描可做；不要求生图环境登录，不compile、不claim。缺少执行环境时保留待校验草稿。缺照片或考据资料另列待办，不伪造确认。用户确认分镜后才将相应卡片标user_confirmed；gold模板先复制为本次草稿。
4. **生成就绪**：明确要求按方案生成后执行 `CLI preflight --workspace WS`，核对照片体检与已有同意（成年、本人或已获同意，照片会发送给图像服务）。照片里的人如果不是你，请先告诉对方要做什么，并取得对方单独同意。已有有效记录沿用，换素材时按实际变化核对。角色需要gold或temp_confirmed，定妆表仅用户另行要求才制作。照片同意用 `CLI consent` 记录，用户无需背参数。
5. **生成范围**：每套五张对应最多五次调用；多套按本次明确选择合计（如三套最多十五次），失败也可能计次；不自动重试、不追加。只准备、安装、开发或讨论中的继续不是生图授权。用户明确“按这套拍”即可，不再重复问。登记本次范围、照片、卡片和实际参考，预算丢弃项必须如实说明。
6. **执行**：按宿主路由调用既有流程。Codex逐张compile-shot→imagegen→set-record；CLI用generate-set。中断先set-status核对，不自动续跑；首张失败取消余下四张，后续单张失败不重试。内部计数不等于服务商账单。
7. **检查与交付**：按status-and-dod目视人体、角色害羞、本人/环境表现、摄影目标与动作；每张verify、frame-check、deliver。逐张将实际成图与本套已出图并看，比较身体姿态、头向视线、表情、景别和故事推进；只换背景或道具不能算姿态变化。若非用户要求的重复已经影响整套，先停止继续生成并说明，按已有授权决定是否调整；没有可辨识的整组变化就不能声称套图通过。审计、文件完整性、画质与用户验收分别说明，不能互相替代。保留原字节，不把生成成功说成验收通过。
8. **反馈与修订**：先区分局部修改与整张重拍；场景已获认可、仅本人感等局部有误时，按 `references/series-creation.md` 的“已认可画面的局部修订”选择方法，Codex执行边界见backend-codex-native。逐张收集本人感、角色、异常及本次目标是否达成：CLI正式交付按实际回答record-verdict；手工原生局部测试仅在私有工作区记录用户通过及选用版本，保留旧版，不伪造CLI sidecar或整套完成状态。明确指定重拍某张就是该张一次新任务；保存新卡/新request及旧版本，沿用当前宿主。单张compile可加 `--chain-set <原套图卡>` 保留已校验首图；若首图本身是要纠正的问题，不盲目继承。Codex用原生工具，CLI才用generate-exec --authorized-count 1。不要绕过失败账本复用旧调用。

素材登记与本人感评估读 `references/photo-guide/README.md`：保留私有原字节副本，区分单图绝对验收与相对偏好；一张清楚的正脸照就能拍，多给侧脸是否更像尚未对照；露脸镜头转头超过约 20° 时本人感明显下降，其余角度边界未经实测不承诺。

## 用户意图与调用范围

- 身份照片按用户指定路径读取，生成与私人记录写在 `WS/`。用户明确要求的开发案例整理可复制选定生成成片与去除私密信息的说明；不据此复制原始自拍或私人日志，不据此发布。
- 明确要求拍摄当前已确定的套图即为生成请求，无需固定口令或再次确认次数；明确要求重拍某张即为该张一次新请求。必须对应当前卡片与已同意的照片。只准备、安装、开发、发布或笼统继续讨论，不据此生成。CLI的 --authorized-count 是内部次数上限，由本次已确定范围填写，不要求用户念出参数。
- 临时定妆表是额外图片，只在用户明确要求时生成，不随套图自动附加。既定张数耗尽后不自动扩展；失败不重试。Codex自身权限按宿主正常机制处理，不把本技能的对话规则说成安装要求或程序层硬拦。
- 不读取、不回显任何 `.env`、API key、账号 token。

## 红线

- 本流程不执行 `git push` 或远端发布；用户要求的开发台账提交只在本地完成。
- 角色永不露脸；用户本人每套 1–2 张清楚正脸（封面＋情绪最高点），其余用背影、只拍手、越肩、剪影、远景（user.presence），靠整组一致的发色、衣服、首饰认人，不出现正面无脸人形（D25）。害羞是构图思路，不是承诺：画面偏差靠自检兜底。
- 演员姓名扫描用于分开造型选版信息与虚构角色描述，避免无意改变角色或主角身份；不是“所有公众人物图像均违法或平台禁止”的判断。涉及真实人物的请求按实际肖像、隐私与真实性条件处理，不把真人偷换成虚构角色。
- 不把版权、国别、题材或虚构角色年龄当作一律禁用条件；权利与平台要求只按确切适用情形说明，见 `references/rights-cplus.md`。
- 景别、角色数量和卡片字段按当前 Schema；超出实现能力时说明技术限制，不解释为法律禁止。不代发帖或替用户操作发布账号。
- 平台拒绝时如实说明实际原因，禁止改写提示词绕过审核；超时与失败都不自动重试。对用户可接受的目标可提出内容实质不同的安全替代方案，按已有授权与新请求处理，见 references/dialogue.md“内容审核拒绝后的恢复”；不重复提交被拒内容、不保证零拒绝。
- 当前身份参考素材限成年人照片，不将这一素材范围套用到虚构角色年龄。交付原图不得重编码。

## 状态与完成（Definition of Done）

完整定义见 `references/status-and-dod.md`。套图账本状态：`pending` → `claimed` → `generated` | `rejected` | `failed`；第 1 张失败时其余为 `cancelled`。一套只有在 5 张都完成用户自检、且 `verdict: accepted` 时才算完成；没有自检之前不得说“已完成”。
