# 选片与身份验证

公开测试版仅提供文字选片说明，不附带人物图片。

- 优先清晰、无遮挡、无明显滤镜的原照，正脸便于对照；已有其他角度可补充。不要把两张或三张说成已验证的最低要求，也不要仅因单张或侧脸拒绝准备。
- 记录素材实际覆盖的头向、俯仰、表情与遮挡；只凭目视不写精确角度。目标超出已提供的角度时说明身份效果未验证，可建议补照；用户仍可选择有限次数尝试，不自动增加调用或限制为只拍正脸。
- 仅支持已确认成年、本人或已获主体同意的照片；素材同意、文件质量与身份相似度是不同检查。
- `CLI consent` 会把本次登记素材按原字节存到 `WS/input/originals/<sha256>.*`，在 consent.json 中保留原路径、archived_path、sha256、尺寸及字节数。副本损坏时停止，不覆盖。重复登记相同字节不重复记录；reset只重置同意记录，不删除原照。
- 历史记录不自动补档，原件不存在时标记缺失，不把另一编码版本默认为同一照片。生成仍使用明确传入的路径；需要从副本恢复时显式使用 archived_path，并沿用按摘要绑定的同意核对，不静默替换。
- 私有工作区应位于仓库外且不在临时目录；原照、私人日志不进入公开案例、Issue或发布包。

## 评估记录

每张分别记录：实际输入及输出摘要、期望姿态、实际姿态是否符合、助手目视意见、用户是否觉得足够像。两图比较另记相对偏好；“右边更像但都不像”不能记为右图通过。

身份评价状态采用本私有评估记录的 `pending`（待用户评价）、`accepted`（用户明确认为足够像）、`rejected`（用户明确认为不够像）、`uncertain`（无法判断）。保留用户原话；与CLI正式交付verdict分开，不能自动提升整图或整套验收。

效果范围标为：`unverified`（无匹配验证证据）、`observed`（有实际样本但尚不能证明稳定）、`validated_for_scope`（有用户绝对验收与重复结果，且明确列出人物、输入包、输出条件、次数和局限）。这些是私有评估字段，不新增CLI账本状态；文件哈希/静态测试通过不能把效果范围提升为已验证。不从单个人推广到女性群体，不把AI模特视角当作真实身份真值。
