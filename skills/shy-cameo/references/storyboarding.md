# 写分镜

按需读：写卡看「卡片字段」；新造型看「衣装、参考与穿戴阶段」；安排互动看「陪同角色的存在感」与「道具选择」；只准备文字先看「只准备分镜」。多系列差异见 [系列与项目](series-and-projects.md)。

## 只准备分镜

先写五张有区别的动作与画面，并把草稿存为 `WS/cards/set-<id>.json`。有本地执行环境时，用 `CLI check-pose-variety --set-card WS/cards/set-<id>.json` 检查套图和每张分镜的 Schema，并读取 JSON 中的 `warnings` 构图建议；另做姓名扫描。构图建议不阻断，保留用户指定的相似姿态或连续机位。这一步不要求确认或照片，不写账本；生图登录与 `preflight` 留到实际生成前。

缺执行环境时保留文字方案和待校验草稿，说明尚未校验；缺照片、角色确认或实景来源列为待办。用户确认方案后才记 `user_confirmed`；确认方案与要求生成分别记录。

五张按故事需要安排，`cover/wide/interaction/shy/ending` 是账本槽位，不固定第四张遮脸或每套递物。人物可辨、伙伴害羞；构图与视线数量建议用于改善方案，尊重用户指定的同景或相似姿态。套图 `ip/play_mode/style/aspect` 保持一致；各张 `visual` 表现须属于已确认的整体方向。

## 分开确定四件事

1. **身份**：traveler来访者，fitting主题试装，in_story剧情参与者。剧情身份可按用户所选角色或身份表达，不强制无名。场景是故事世界并不自动意味着扮演剧情角色。主角在故事里有任务、有角色名用in_story；只是到场看看、合影、游览用traveler。只想换上某角色或主题的衣服拍一套（如“换上飞天的衣服拍一套”）用fitting；片场、后台、化妆间等幕后套默认fitting，用户明说只想探班才用traveler（幕后试装与角色距离），不另设玩法：有陪同角色挂经典合拍，地点为主挂旅行，片场或剧情感挂类型电影。
2. **衣装妆发**：costume或outfit、hairstyle、makeup适用于各身份；按用户确认内容传递，不以一次只改一项或必须三件符号作为门槛。本人可辨与清楚露脸、陪同角色害羞仍保留。未指定妆发时沿用本人，不自行加妆。衣装选择、参考用途与穿戴阶段，以及性感、显形、裙装、高端感等诉求的落实见 storyboarding.md“衣装、参考与穿戴阶段”；模式与性别不决定固定制服。
3. **视觉表现**：新方案用可选visual分别确定subject、environment和characters。值为photographic、animation_2d、animation_3d；characters省略时跟环境。style保留旧卡兼容，visual存在时优先；不按IP名字偷偷改风格。
4. **场景与拍法**：film_context/setting写现代后台、故事世界、生活场景或实地；lighting写光源；cinematography写有用的摄影选择。场景例子不是封闭菜单。

| 用户选择 | visual.subject | visual.environment | 说明 |
|---|---|---|---|
| 本人动漫化进入动漫 | animation_2d或animation_3d | 对应动画表现 | 本人也重绘 |
| 真人进入动漫画面 | photographic | animation_2d或animation_3d | 本人保持真人，环境保持动画；陪同角色按选定动画设计 |
| 真人进入真人化故事 | photographic | photographic | 整幅真实材质和电影/写真表达 |

以上是常见组合而非新白名单。旧卡仅style=anime仍采用原有日式二维表现；仅style=realistic为摄影表现。旧主题原来依赖IP特殊模板，新生成前将期望表现显式写入visual并确认，不重写历史request/案例。

## 卡片字段

- scene使用schema_version=2；set使用schema_version=1，五张shots。新卡status=unverified，用户确认该方案后改为user_confirmed。gold 是库内已确认模板的质量状态，复制到本次工作区为草稿并按本次选择确认，不直接作为本次授权。
- play_mode：classic_presence、archetype至少一位陪同角色；original_text、genre_scene、opera_costume按实际创意选择有无陪同角色；location_checkin按归类顺序：用户说让角色带路、当导游才写角色当导游（试验），只说地点就写单人。最多两位陪同角色。pet_daily（试验）只有主角和宠物、不加角色，套图卡必须有 pet、五张分镜都写 pet。玩法选择与复合需求见路由说明。
- user.mode：traveler、fitting、in_story；in_story需要role，戏曲需要行当role；fitting需要costume或outfit。衣装按 衣装搭配（适用于：通用）设计：用户已选衣装和审美偏好优先；未指定时先看身份、当下活动与故事阶段，再结合环境、动作和目标气质选择类别、版型与材质，并回看配色和场景光。原照的发色、穿衣风格与领口是可用线索，不代替本次造型设计；不把居家、性别、片场或玩法绑定为固定制服，也不自行改变用户的露肤偏好。已有信息足够就直接拟方案，不增加逐件选衣问卷。所有身份均可按实际选择填写costume/outfit/hairstyle/makeup，不再把衣装与剧情身份互斥。不要写互相冲突的两套衣服。
- visual：可选，subject/environment必填，characters可选；各自为photographic、animation_2d、animation_3d。新方案用它明确人物/环境表现。style保留realistic/anime以兼容旧卡，visual优先；新画面效果不从作品slug推断。新卡只按visual写画面表现，style照套图统一填写即可；真人进二维画面＝subject=photographic、environment=animation_2d。
- film_context、setting、lighting、cinematography：空间时代、可见环境、光源与本张摄影设计。电影感的判断见本页“电影感”，不堆叠8K/史诗等空词。lighting 写成场景里看得见的实景光源（工作灯、吊灯、门缝光、傍晚天光），给出亮处落在哪、哪里留暗；有 visual 且环境为真人摄影的非打卡镜头，默认偏暗、背景比主角暗一到两档，不写正午满屏日光、不把整张提亮；打卡旅行不压暗，编译器改加"旅行电影布光"（白天户外不把整张压暗，靠方向光、人比背景亮半档到一档、轮廓光、亮暖暗冷、浅景深）；没有 visual 的写实主题写真不套这条，按各自场景写光；露脸张写脸部光时不写"均匀照亮整张脸""脸上没有阴影"（等于手机平光，卡帕多奇亚 mood-r2 被判"跟手机拍的一样"），写"主光从左前方约 45° 给脸柔和的方向感，脸整体受光、五官清楚，明暗放在背景和轮廓光上"，也不写"半张脸在阴影里"；用户或作品要明亮日景时，lighting 里写明“明亮日景”，编译器就不加电影布光，光仍要有方向和暗部。明亮日景只是不压暗，仍按电影级画质写（编译器对所有图都加）。
- 夜景与暗场景：先定唯一主光源并写清它在主角哪个方向（如左前方偏低的一盏灯），脸的亮度和方向都来自它；其余光源少而暗、放远处虚成光斑，不照到主角，不在卡里并列写四五个光源；cinematography 写三层——暗而虚的前景一角、被主光照亮的主角、暗而虚的背景，主角和背景之间隔一片暗，背景建筑与灯火不贴着主角；背景灯火写成"只剩三五颗虚掉的光点"，只写"零星"压不住（夜景整套第 1、2、5 张小镇灯火仍偏密）；逆光剪影张写明"主角正面不受光、全黑剪影，只有边缘一道轮廓光"；暗部占画面一半以上。
- user.action：本张动作与视线，position为left/right/center。回头或交接说明躯干、肩膀、头和镜头关系，避免互相矛盾。露脸张让主角看的东西放在镜头方向，不写侧面的拳头、屏幕；背影不写单腿站、交叉腿、扭身这类易画拧的姿势，故事不需要就不拍腿脚。碰到烫的、带火的东西按现实做法写：热碗用托盘或垫布端，吹凉再尝，人离滚锅和明火一步远，头发不垂向火。
- characters：character_id、variant_id、position、action与character_presence。局部特征写visible_parts；expression通过动作表现，不据此画脸。角色卡的完整脸部/全身特征不整段注入，以免无脸拍法变成全身角色；需要辨识的袖口/毛色/道具应写进visible_parts或action。
- character_presence：hand、shadow、back、cropped（头在画框外，只露肩以下）、peek（从门框、树干等遮挡边缘露出局部，不露脸）、cover（用道具遮脸）；没有露脸方式。cover配cover_level：face只挡脸（如举扇挡住脸，冠帽等头饰顶可露在扇子上方），full_head连头一起挡（如身体藏在门框后、只露举着的灯笼）；不强制第几张使用；side_profile旧值改成合适的无脸方式。雪人、机器人这类非人角色只拍背面、手或影子时容易变成普通雪人或普通机器：压测卡里 visible_parts 已写三段雪球与头顶树枝，仍画成普通雪人，写轮廓不足以补救；cropped裁掉头、cover挡住头对这类角色同样只剩普通身体。主要靠脸认的非人角色不适合害羞出镜，确认分镜前先告诉用户可能认不出，建议换角色。
- framing：close_up头肩、waist_up到腰、knee_up到膝、mid_interactive到大腿、full_body完整身形、wide环境远景；camera_angle可选high/low/side，默认平视。远景本人感未作稳定验证；压测中全身远景露脸镜头相似度偏低，露脸镜头不用 full_body/wide，远景配背影。
- user.presence（可选）：face 默认露脸；back 主角背影、hands 只拍双手动作。越肩、逆光剪影、背影远景都写 back（剪影是背面轮廓，不写正面黑脸），每套只留 1–2 张 face。不露脸镜头不能配 camera_angle=side。戏曲扮相也可用背影（看头面、靠旗、水袖）或只拍手（兰花指、水袖、扇），避免 5 张同头饰正脸雷同；戏曲不露脸未实拍验证。
- props及prop_specs：按[道具选择、搭配与状态](storyboarding.md)先选物，再在现有字段写本镜实际可见物、规格、用途与状态；不用全套清单强加每镜，不靠道具名替代动作。
- costume_keys是可选连续性短名；不强制填写或凑数量。aspect新卡默认3:4，2:3为现有兼容选择。
- source_ref仅元数据，不进入提示词；角色rights_tier/version_labels也是来源元信息。用户原话用于理解，不把整段对话或秘密复制进卡片。

## 衣装、参考与穿戴阶段

用户只问穿搭或机位选衣时，停在所问的造型方案；不要自动扩写整套分镜、写卡或索要生图素材。

沿用 outfit/costume 及可选妆发字段，在已有方案里说明本套基础衣装和真正需要的变化，不新增必填表或固定制服。服饰同时服务人物气质与故事：生活写实、精致写真、舞台或幻想可有不同选择；已知的性感程度、舒适与露肤偏好沿用，没指定就按现有造型拟定，不因性别、真丝或睡衣自动增加露肤。妆发未另选时沿用本人，不为补全服饰擅自改发型、妆面或身形；用户主动要求的变化按下节落实。

先分清新造型策划与已有画面修改。新套图先回答两个问题：这个人为什么会穿这套衣服来到这里；这套衣服在本次镜头里要呈现什么气质和线条。把身份、活动、环境与用户审美一起判断：现代人走进故事世界仍可穿现代衣服，不因山洞或古代布景自动换古装；卧室可按亲密、性感、慵懒或日常目标选睡裙、睡衣或其他合适造型，不固定为某一种。已有画面只修改本次范围，不为搭配而附带重设已保留的动作、宠物位置、机位或灯光。没有原图依据的潜在问题不能当成已确认缺陷。

在五张分镜前，用一小段可看懂的造型方案交代完整搭配与理由：上下装或连衣款的轮廓、长短和穿法如何配合，颜色的主次、材质的软硬或光泽如何服务气质；鞋和配饰按实际活动及可见范围选择。只列“浅色上衣、深色裤子”或补一句“高级感”不足以说明设计。将具体衣物写入现有 outfit/costume 字段，分镜写本镜可见的穿戴状态；不新增参数表、选衣问卷或额外定妆图。

按计划机位检查服饰的作用。背影看后腰是否合体、上衣下摆是否遮断腰臀线、裤裙的后片与口袋是否支持想要的轮廓；修饰臀部曲线可以来自合体牛仔裤、裤裙剪裁和姿态，不固定为紧身运动裤。坐姿或卧姿看衣料如何垂落、领口与裙摆如何变化、露肤是否符合用户意图；近景关注领口、肩线和手边材质，不为展示全套衣服改变镜头。用服装和摄影修饰线条，不自行把用户的身形比例改掉。

搭配需有画面理由，不用“高级、性感、休闲”代替设计。服装类别、材质和气质是不同维度：针织的柔软与纹理可表达亲近，也可用贴身轮廓表达性感；真丝的垂坠和光泽可表达流动与精致，但强高光可能抢走脸或互动；白T与牛仔可服务轻松日常，也能通过剪裁和摄影呈现精致。结合活动、温度和动作选择合适版型与穿法，不能用“居家必睡衣、女性必真丝、高端必华丽”作固定答案。这些是创作判断，不是面料真实性或画质保证。

先看场景的主色、明暗、饱和度、纹理及伙伴颜色，再决定衣装与场景的关系：融合用相近色调或材质回应环境；突出用颜色、明度或轮廓区分人物；有意反差可用冷暖、粗细质感或时代风格对照服务时装感与视觉冲击。用户要反差时不强行改成和谐，未指定时按本套故事与审美选一种主关系，不默认最大对比或照抄互补色。生活叙事重活动可读，时装或幻想允许更强反差；无论关系如何，衣服都要接受同一现场光、透视与接触，避免像贴图。颜色不能只在色卡上成立，要检查受光后是否偏色、与背景粘连、反光压过面部或宠物。

搭配理由要能在本次成图中检查，例如上衣下摆与裤腰的衔接、暗色衣料上猫的轮廓、低光泽布料在床边侧光下的垂坠。生成前写清预期，成图未呈现就记偏差，不事后替随机结果补理由。用户已选衣服时，优先使穿法与现场光适配，不擅自换款。

整套审美按每镜的叙事作用落实，不把每项造型目标机械复制到每张。人物写真可表现剪裁与肩颈，宠物、手部或道具细节以互动和物件为重点，可只用袖口或配色维持衣装连续；无需让每镜都展示身体、性感程度或完整服装。局部重点应在生图前确定，这属于构图设计，不是审核词过滤；不能承诺这样就不会被拒。实际拒绝后的处理见 generation.md“内容审核拒绝后的恢复”。

同装段保持关键版型、材质、配件与穿法；有剧情依据的穿上、卸下、淋湿等变化，逐张写当下状态。试装写真可以整套全装，后台也可从已穿戴完成开始，不强制每套出现穿脱过程。鞋袜和配饰按镜头可见性及动作需要说明，不为验鞋改变已定近景；需要作品/剧种忠实还原时才按所选版本核对，原创转译如实标明。

区分身份参考、服饰参考和待修图的用途；首图服饰有误时不盲目将它作为服饰基准。套图首图串联仍用现有通路，换装张明确本张变化覆盖哪些继承项、哪些继续保持；旧图只用于保留本次不改部分，不把衣装缺陷一并保留。局部编辑按 delivery-and-revision.md 与当前宿主边界执行，不承诺区域外像素不变，也不为换装默认增生定妆图。

看实际成图中的类别、轮廓、可见材质/光泽、关键件与穿戴阶段，同时看人体、接触和附带变化。未入镜的鞋、下装、妆面等记未观察，不能凭提示词判通过；真丝等是视觉设计，不证明真实纤维。亮度和材质形容词可能不生效，已接受的局限保留，不以重复追加生图凑通过。

### 身形参考与确认

按照片可见范围判断当前镜头需要的身形信息：清楚可见或已确认的部分直接沿用；缺失且会影响画面时，只核对这些部分。用户需要看参考时，读取 [身形参考图库](body-reference.md)，展示已通过检查的固定图片，允许选图、组合描述或都不像。参考图不能替代本人脸部身份，图库未完成时如实说明，不自动临时生成补齐。将确认内容写入现有描述字段，再用于写真；不强制分类问卷或重复确认。

### 从用户愿望到造型变化

“性感一点”“身材好一点”“穿裙子”“高端一点”是正常的造型诉求。本人辨识度是持续检查的目标，不是保证面部绝对不变；衣装、妆发、身形与摄影可以按本次意图变化。用一句具体画面解释所选做法，信息足够就落实；只有不同理解会明显改变结果时才澄清，不让用户填写变量表，也不把可变项全部自动改动。

| 用户表达 | 落实方式 |
|---|---|
| 性感一点 | 将已知偏好落实为剪裁、肩颈露肤或姿态；未说程度时先拟自然轻度方案；用户后续明确要求更性感时按其反馈调整强度，不自动升级为大幅露肤或改胸腰臀。 |
| 身材好一点 | 默认先用合身剪裁、腰线、姿态与摄影改善观感，不自行改变身体比例；明确要求收腰、修长等时支持对应的自然变化，写明改变部位及保留部位，不再用“全部体型原样保留”抵消目标。 |
| 穿裙子 | 给出适合场景活动的裙型、材质与长度，联动检查坐姿、行走、裙摆和接触关系。 |
| 高端一点 | 用剪裁、面料观感、配色及适量配饰具体表达，不自动等同于品牌标志、珠宝或更多露肤。 |
| 多项组合 | 同时满足明确选择并检查相互影响；一次只改一项可用于诊断失败，不是限制用户创作的规则。 |

服饰、妆发和摄影分别写入现有对应字段；明确的身形表现可在 user.action 描述中与动作一并说明，不新增未支持的字段。编译后检查实际请求是否保留变化与保留项，不能只停留在方案正文。沿用参考时，只继承本次保留的内容；明确修改的衣装、妆发或身形覆盖旧图的对应约束，脸部身份依据仍保留。

比较输出与输入的可见差异，同时检查本人感与非预期变化。袖口、腰带、膝部、遮挡或鞋款也可能随换装漂移。改变身形时检查衣服是否随之合身、肢体及背景直线是否自然；外套、手臂或裁切遮住目标部位时，说明效果不可判断，不靠提示词宣布成功。未见变化记未达成；需要新的可观察对照时先说明新的比较基线，在已有授权内执行并保留旧失败，不能回填为原对照通过。不承诺厘米级改变、衣下几何或全模式稳定锁脸。

## 陪同角色的存在感

默认同时满足不露脸、角色可辨与互动可读。按本张实际可见区域选择体态、毛色分区、服饰或标志性物件，写入visible_parts、action与cinematography；不把完整脸部特征注入提示词，也不靠角色名字代替可见依据。只有普通黑手掌等通用局部时，不能据此承诺能认出特定角色。可优先用背影或裁掉头部的肩背与躯干，兼顾主角的脸和动作；不固定面积比例或新增确认门；每套数量只有 角色中景背影（适用于：有陪同角色） 一条下限（至少 1 张中景背影，见下段）。真人感角色在现代生活场景（逛街、旅行、日常）穿现代装时（片场、后台、戏中照穿原著装）：现代剪裁，至少保留 2 个本张可见的一眼认出的元素（悟空：紧箍、金箍棒、毛手、尾巴），写进 visible_parts；动画造型角色保持原造型不换装。有正反面之分的饰物按朝向写：背影只见背面，例如紧箍正面纹饰在额前，背影只写素面后半圈。

先安排两人在做什么、看哪里、离镜头多远，再选择支持辨识的最少可见特征；后脑、肩背、躯干和裤腰是备选依据，不是每镜必须集齐的清单。陪同角色不应为了露全特征贴近镜头成为巨大前景：离镜头近时只露手、手臂、尾巴等小面积局部，身体只以中景、带标志服饰的背影出现；毛绒或动画角色画成近处大块身体容易像人穿玩偶服，缩成远处认不出的小点又失去辨识；每套至少 1 张让角色以中景背影出场，看得出身形与标志服饰，离镜头和主角差不多远、不比主角近，用门框、窗格等实体挡住一部分，其余镜头再只露局部；整套只露手爪就成了认不出是谁的普通手爪；封面（第 1 张）要不说也认得出：有陪同角色时默认就把这张中景背影放进封面，站位比主角明显远、明显小（主角身后的通道或房间深处），离她近、与她等大会像玩偶服；只露手、爪、影子的封面认不出是谁；封面出图后做盲测：宿主能派无上下文子代理时派 2 次；拒绝写明了原因、该角色没有出图记录、或再试仍被拒，都用局部版定稿并向用户说明（拒绝后的处理（适用于：有陪同角色），出图记录按角色分别算）；用户的手与角色的手、爪不直接接触（不写拉钩、握手腕、手递手，易粘连多指），中间隔一件物体（同扶一根竿、同握卷轴两端）或让角色局部在后景略虚；从画外伸进来的手、爪、尾巴要有合理来处（门后、桌对面、画边看得见的手臂延续），不凭空横进画面，也不画成没有身体的巨大前景手爪；角色身体需遮挡时用门框、木人桩、窗格、屋脊、器材箱等实体，不靠蒸汽、旗杆、灯架；检查主角是否仍是视觉中心、裁切是否自然、动作接触和视线是否在回应同一事件。背影人物也要参与动作，不能只把大块背部摆在主角旁边；互动镜头不默认强迫主角看镜头。主角的脸朝向镜头（正脸，左右转约 ## 带宠物的套图

用户说明的相处习惯要贯穿各镜动作。明确“黏人、喜欢被抱”时，旅行中的移动、停留与休息围绕抱着、贴身依偎或受主人承托来组织，写清身体接触和支撑；变化来自活动、机位与景别，不靠每张把猫放到不同街角。不能仅因同框就把独自待在远处的猫判为陪伴关系成立；用户明确喜欢独立跟随的宠物则按其实际习惯设计。

宠物的意义是陪伴：整套讲"我带着它去了这里、一起做了这些事"，不是风景里偶然出现一只动物。先定陪伴方式，再写每张动作。陪伴方式有四种：抱着（抱在怀里、趴在肩头、从背包或披肩里探头）、跟着（在脚边、前面半步回头等她、并排走）、一起做事（一起看同一样东西、她的手和它的爪碰同一处）、各自待着（她看风景，它在身旁打盹或张望）。用户说过它平时的样子就照着选；没说时问一句"它平时更爱被抱着，还是跟着你跑？"，不答就猫默认抱着＋各自待着、狗默认跟着。一套至少用两种，五张不摆同一个姿势；至少 1 张有身体接触（抱着、手放在它背上、它靠着她），手只放在背上或托住身体，不握爪。

封面要一眼看出"她是带着它来的"：抱着或紧挨着，两者都在焦点上，不把它放在远处当点缀。每张的分镜卡 `pet` 写三样：它在画面哪个位置（她怀里、她左肩、画面左下前景、她脚边）、和她什么关系（贴着、互相看、看同一个方向）、在做什么；不写"在她身边""在旁边"这类出了画框也成立的位置。露脸张带宠物时，要么把它抱在胸前或肩头放进头肩框，要么景别放宽到腰上中景；它不挡脸、不高过下巴。只拍手的张可写她的手和它的爪碰同一样东西；背影张适合"跟着"或"依偎"。既然是陪伴，默认五张都有它，只在剧情说得通时才空一张。例：坐着看明信片那张，猫窝在她怀里，她一手拿明信片、一手搂着它，一起看；坐在高处背对镜头看热气球那张，猫依偎在她身侧，两个背影靠在一起看同一片天。

套图卡 `pet.look` 写品种、体型和最明显的特征（如"英短金渐层，圆脸大眼、身子圆滚滚、短腿"，60 字内）：拿到照片先自己看图认，再跟用户确认一句，不确认不写品种。只写照片里看得见的：毛色分布（哪里橘哪里白）、眼睛颜色、耳朵大小、眼神；毛蓬松不等于胖，体型必须问主人一句，没确认不写"胖""圆滚滚""短腿"；宠物照里它若只占一小块，先裁成只剩它的特写（裁后的图重新 consent 登记）再用；封面写它睁着眼、脸朝镜头，不写眯眼、闭眼、背对；宠物和手、杯子、吐司这类小东西同框时，写它的大小参照旁边的东西（"猫头只比她手里的牛奶杯大一点"）和它离镜头多远，景别放宽到看得出前后距离，不写"只露出脑袋"的特写；每张的 `pet` 也不再叠"圆脑袋""圆背"这类体型字。动作按体型三档：猫和小型犬能抱（怀里、肩头、背包探头）；大型犬（金毛、拉布拉多、哈士奇这类）不写抱，改成靠着她、并排走、趴在脚边、把头搁在她腿上。和宠物过日常（pet_daily）：一套只讲一件小事，五张同一天同一个地方，按起（发现/开始）→承（靠近）→转（互动的小意外）→合（最亲近的一刻）→尾（安静收尾）排；场景是自己的家或日常去处（家门口、楼下公园、常去的咖啡馆）；光按"生活电影布光"写一个屋里的实景主光，不写"明亮日景"；露脸张仍守 露脸张数 的 1–2 张。屋里空间小，不露脸的几张最容易都写成"从身后越肩拍"：两张背影或越肩之间，机位方向（身后、侧面、对面、窗外往里）和景别至少换两样；收尾那张写远景时要写清"人和宠物只占画面三分之一以下、大片环境"，并换一个机位方向。宠物要放在稳得住的地方：地板、床、沙发、宽飘窗的垫子、桌面中间、她怀里；写它趴在台子上时写清台面多宽、它整个身子和四只脚都落在台面上；不写落地窗前的窗台、桌沿、栏杆这类窄边。

## 各玩法写法

- 经典：按用户所选作品版本与关系创作；后台必须让摄影设备、工作活动或布景关系可读，故事世界用相应环境与事件区分。片场、后台、化妆间等幕后场景：默认user.mode=fitting，用户试穿该作品风格的戏服（取作品标志配色与款式），陪同角色从画外帮整理、递道具；用户明说只想探班或穿自己的衣服时才用traveler并穿时尚日常装（幕后试装与角色距离）。每张安排一件后台正在做的事（理衣领、够道具架、接道具、撞见偷吃等），热闹靠中景真人工作人员在忙、背景可辨不全虚成光斑（幕后试装与角色距离）；画面里的戏服、道具优先用该作品一眼认出的标志物（如金箍棒、凤翅紫金冠（原著）、阿檀的客栈算盘），不用泛泛古装；作品辨识由角色、衣装、空间和必要道具共同承担；后台活动可空手，普通杯瓶无需换成标志物或加图案；不印真实片名或剧组名文字（生图易乱码，也像冒充官方物料）。剧本例外：按真实剧组 A4 稿画——左上角订书钉、翻过的页对折到背后、几行荧光笔划线、夹一张彩色改稿页露出边角，字迹虚、读不出，不加作品图案（爪印封面像绘本），作品关联靠同画面的戏服、角色或其他标志物。
- 戏曲：明确行当、衣装头面、妆面与后台/舞台；以主角身段或准备活动组织动作，不凭空引入第二个人。浓妆后最容易认不出本人，一套按“素颜/半妆 → 上妆过程 → 全妆登台”排，前 1–2 张露脸锚定本人；全妆默认淡彩：少贴或不贴片子、保留本人眉眼和脸型、胭脂减淡，写进 makeup；用户要浓妆照做并提示可能不像；全妆镜头多用背影、手、远景。
- 原著：原文支持的事实与创作补充分别记录；用户选改编版本时如实说明依据变化，不假称原著逐字还原。
- 原创：写清原创人物的局部辨识与任务关系；in_story体现实际行动及结果。
- 类型电影：片型、年代和用户指定参考可以记录；无cast时用主角、环境和物件叙事；若有递物手或神秘人背影，作为陪同角色写入cast并遵守害羞设定。
- 旅行：同城五镜或五国各一镜按用户实际范围；地点变化明确写在每张setting，不默认扩张为25张。用户说让角色带路、当导游时由该角色当导游（试验）：背影走在前面领路、举小旗、指方向、递地图或门票，不露正脸；只说地点就写单人，热闹街景远处可有看不清脸的路人。电影式旅行由用户目标决定。

## 电影感（所有成片默认）

所有成片默认电影级画质与电影感：像电影里的一帧，不是手机随手拍或平光广告照；编译器对每张都加这条，动画画风按动画电影画面写。电影感不等于发黄、加颗粒、压暗、加黑边：故事剧照/类型电影强调叙事，旅行也有电影布光：白天户外不压暗，靠方向光、人比背景亮、轮廓光和冷暖分离，戏曲优先舞台与服饰表现。压暗的电影布光（电影布光）仍只按原条件加。

写入本张真正有作用的摄影选择即可，不要求每张填全参数：
- 镜头为何在这里：近景看反应，中景看交接，环境镜头说明处境；按动作选择视角，避免五张只有背景不同。
- 光从哪里来：窗、舞台灯、门外、火光或日光与人物朝向相容；脸部、道具、背景有层次，不为了气氛损害本人辨识。
- 空间怎么组织：前中后景、人物与角色的距离、视线和交接位置；浅景深服务重点，不把故事背景全糊掉。
- 动作发生了什么：每张有可读瞬间，下一张体现结果；同一空间也能有节奏。避免所有主题都“递物、举手看影子”。
- 美术与色彩：按目标选择材质、年代、服饰和环境之间的协调或有意反差，说明如何服务故事或视觉冲击；具体搭配见 storyboarding.md。反差不取消现场光、透视与接触的统一；混合真人/动画时保留各自质感并协调接触阴影。

当前景别可用close_up、waist_up、knee_up、mid_interactive，以及full_body、wide（环境远景）。全身和远景更难维持本人辨识，应说明取舍并检查实际结果，不以未验证说成禁止。焦段/相机数值只是创作提案，不把它写成真实拍摄记录。

成片检查同时回答：像本人吗、陪同角色及害羞方式对吗、人体动作合理吗、本人与环境表现对吗、本张故事动作/空间和所选摄影目标实现了吗。电影感只有文案或编译通过时标“已设计，效果未验证”；旧图局部有气氛不能证明新版稳定达到目标。

## 真实机位与参考

用户要求真实地点/可复现机位时，在卡片旁保存地址或地图入口、实景来源、观看方向、已知遮挡与未知部分。坐标、焦段、机位高度没有证据就写待核；AI输出不能证明地点组合存在。虚构旅行不强加考据门。

## 修改与长度

修改对应字段，revisions追加n、fields_changed与unverified；用户确认受影响内容后标user_confirmed，不重复确认无变化项。760字仅是去空白后长度建议，超长不截断、不阻断、不生图。完整提示词可查；姓名扫描用于防止演员选版信息混入身份，不冒充法律禁令。

## 道具选择、搭配与状态

策划或修改道具时使用；是现有setting、props、prop_specs、action和摄影描述的决策方法，不新增必填表。

1. 先沿用用户指定与已确认情节，确认本镜活动、人物身份、地点时代、画风和主要焦点。新策划可以提出合理创作选择，已有图只动本次范围。需要准确还原时核对所选来源；原创、幻想或有意时代反差不自动纠正成写实，也不冒充还原。
2. 判断物件承担什么：实际操作、人物互动、角色识别、场景线索或用户要的视觉焦点；一件可兼任，无必要就不加。不用职业/地点标签自动配固定套餐。人物服饰或空间已能交代作品时不再强塞标志物；普通杯子不必变文创杯。留一句选物依据，不事后替随机道具补故事。
3. 把物件与衣装、环境、伙伴一起看：颜色明暗饱和度、材质反光纹理、形体尺寸和数量，决定融合、突出或有意反差。视觉冲击可以是目标，但焦点归属要清楚；材质仍受同一光线、透视与接触支配，不能只写高级或固定互补色。
4. 先从用途反推整体动作：物件的结构、受力、朝向及作用范围能否共同完成当前活动，而不是只让手接触它。关键部件移动时要同步检查整个物件与使用者的关系；有意风格反差不等于允许未说明的物理矛盾。再明确当前瞬间：有几件、谁持有、在哪、开合/使用/暂停/收起/消耗到什么状态，手是搭放、握持还是操作。合计人物和伙伴的手、宠物承托、器物重量与桌面支持，避免同一只手做互斥任务；可用台面支撑、前后瞬间或减少无关物件，不默认添手或换故事。同一事件中人物与伙伴的身体朝向、视线目标和移动方向应相容，不为同时露脸与背影把同行画成相反方向。近景只要求可见结构可读，不强迫全物入镜。
5. 连续的是物件身份和该保留的特征，不是冻结状态：允许转交、开合、消耗、明确换色/材质，也允许出框。当前可见物写当前规格和动作，不把全套物件表塞进每镜；首图有的东西不必每镜出现，合理重复的标志物不因防重复被换掉。编译的名称匹配只是文本候选，不能识别否定或证明成片可见；本镜不入镜的物件不列当前prop_specs，必要排除说明写清，核对实际提示词是否又带回。
6. 区分参考身份、衣装、道具外观与待修底图；旧图错误不继承，本镜明确变化优先。局部改物件时同时核对受影响的手、遮挡、支撑和投影，不扩到未授权场景；编辑后检查目标变化与其他部分漂移，不保证区域外像素不变。

## 角色卡

`gold` 是维护者确认的库内模板状态，`temp_confirmed` 是用户确认的本次临时造型；它们都不替代照片同意或本次拍摄请求。

角色卡必须符合 `schema/character-card.schema.json`。库内已确认角色在 `library/characters/<ip>/<id>/card.json`，定妆表是 GitHub Release 资产；新角色在 `WS/characters/<ip>-<id>/` 写临时卡。

### 动画角色候选

先写 `temp_draft` 文字角色卡；用户确认造型后可记 `temp_confirmed`，不以制作定妆表为必经门。作品、角色及时期准确记录，不强制成年、不把已有角色改名原创，不沿用“不是卡通”等会抹掉动画身份的排除句。`rights_tier` 只是来源元信息，不是生成许可判断；不能把已有作品写成公版或宣称自动获得商用许可。没有定妆表也可沿用正常编译路径；定妆表仍只在用户明确要求时生成。

### 写临时卡（`status: temp_draft`）
- `identity_features`：只写看得见的固定辨识特征（脸型、毛发、标志性头饰等），依据原著文字和大众公认的标志性元素。有正反面之分的头饰写清朝向（如“紧箍正面纹饰在额前，背后为素面”）。不写任何演员姓名，不写“像某某”。这段只用于定妆表和姓名扫描，不进入套图提示词；套图里要靠什么认出角色，写进分镜卡的 visible_parts 或 action：写卡时先列一份“不露脸也认得出”的局部清单（如阿檀橘红蓬松大尾巴与竹编斗笠；纸鸢背上的折纸大鹤；伞伞墨绿伞身与细长木柄手臂），每张出镜从中取一件；列不出时告诉用户辨识度会弱（角色辨识与故事线）。
- `costume` / `props`：原著或大众熟悉的服装与道具，可用文字神似公认形象；按用户选择准确描述，具体使用与公开用途按 `rights-cplus.md` 说明。
- `exclusions`：容易被画错的方向（例如真人照片不变成猴脸，头饰不误画成身体器官；按当前造型选择，不默认排斥动画质感）。
- `rights_tier`：原著公有领域写 `public_domain`；原创影视、动画角色写 `screen_original`；权利方对使用有明确限制、需单独核对的写 `restricted`。三档都只记录来源类别，不据此一概拒绝或认定可用；维护者确认的角色库收录 `screen_original` 与 `restricted` 前须维护者单独审批。
- `status`：新写的卡是 `temp_draft`；用户看过文字造型（或定妆表）点头认可后改 `temp_confirmed`，不需要先做定妆表；`gold` 只用于维护者确认的角色库模板。
- `lookalike_check.status` 写 `pending`；临时卡不进维护者确认的角色库。
- 同一角色不同剧情时期各写一个 `variant`。
- `episodes`（可选）：这身造型在原著/作品里出现的 2–3 段情节，如美猴王披挂装→"重返水帘洞（第三回）""竖旗称齐天大圣（第四回）"；取经装→取经路上各难。写套图时 film_context 须写明用了哪一段；用户选的情节与造型对不上时先说明，改造型或改情节。

## 三组动画主题示例

这三组是本轮选定的案例，不是法律白名单，也不是其他角色或时期的禁令。

| 主题 | 当前分镜方向 | 造型选择 |
|---|---|---|
| 阿檀（原创） | 狐狸客栈掌柜，客栈里练功、吃面、相互逗趣 | 橘红蓬松大尾巴、靛蓝粗布围裙、竹编斗笠；背影辨识靠尾巴和斗笠 |
| 纸鸢（原创） | 纸鹤屋顶之约 | 纸鹤忍者学徒，月白短打、背上一只折纸大鹤；造型与时期可按用户选择调整 |
| 伞伞（原创） | 雨伞精灵陪主角等雨停 | 墨绿油纸伞身、细长木柄手臂；本组用伞面遮脸，延续害羞角色设定 |

用户点名任何动画作品照常准备（`SKILL.md` 不拦题材）。

### 创作与操作

历史三组采用 `classic_presence` + `realistic`，真人主角保持本人面貌，动画角色保留自身局部设计。`anime` 也是可选画风，不限原创题材；未实测组合如实说未验证，不自动拒绝。主角可以来访或试装，不因外国角色或普通虚构少年而设禁令。

历史样例曾按准备、发现、互动、害羞、余味展开；新方案按本次活动和事件推进，不固定这些节拍。角色不露脸是用户保留的拍法；历史例子第四张用密实道具遮头，其余用手、影子、背影；新方案不固定遮脸镜头位置。伞伞的伞面遮脸是本组的构图选择，不是法律。真实主角照片与虚构角色年龄分开处理。

新增或换时期时准确记录角色卡，保持整组连续，不需要假称成人或改名原创。角色卡确认与照片同意沿用正常流程；定妆表可选，不自动加图。平台实际拒绝时原样转告，不从一次拒绝扩大成全题材禁令。

这三组只有离线编译等程序检查，未有真实成片验收；草稿、照片同意和本次拍摄仍按实际状态处理。三组不是题材许可名单。
