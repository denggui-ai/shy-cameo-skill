# 开场与选题

按需读：已有目标看「开场与方案」；需要归类看「能力归类」；用户说“你推荐吧”看末尾「推荐清单」。多系列的返回与范围见 [系列与项目](series-and-projects.md)。

## 当前支持范围

稳定指已有对应条件下的真人整套案例并获作者认可；试验指功能存在，但当前条件的效果未通过完整验收；对用户说“这个还在试验，效果没保证”。这不保证新角色、画风或新安装包的效果，AI 模特案例也不能提升真人验证档位。下表保留各玩法范围，具体旧验证流水在开发记录中。Codex 有实际使用记录，Claude Code 仍属实验性适配。

## 能力归类：用户不必选择分类

档位以release/CAPABILITIES.md为准。先沿用用户明确选项；多种意图同时存在时，以主要目标选一个play_mode，其他要求保存在身份、视觉、场景和摄影描述中。不因复合需求拒绝或丢掉次要目标；只有不同解释会改变结果时才用一句话澄清。

**归类顺序**（一句话按顺序判，命中即停；没命中的要求写进方案，不丢）：
0. 明确本人当歌手或乐手登台 → 类6；明确去听某位歌手、乐队或虚拟歌手演唱会 → 类7。演出者不当陪同角色；读 [我的舞台与观演](stage-and-concerts.md)。只说“演唱会写真”且身份不明时，才问“你想站在台上唱，还是在台下听？”。
1. 说了让角色带路、当导游 → 类1“带你去旅行”（试验）。
2. 点名了想陪着的角色 → 类1；去哪、做什么写进方案（“和孙悟空去巴黎”“进《西游记》见孙悟空”都在这里）。
3. 整套就是唱戏或穿某身衣服拍写真，没说去哪、没有剧情 → 类2。
4. 说了原著、某部作品、片型或原创角色 → 类3（“进某部作品的世界”没点名角色 → 某部作品）。
5. 说了自家宠物、没点名角色也没说去哪 → 类5（“拍我和我家猫的周末”）；点名了角色或地点就按那一类，宠物用可加项“带上宠物”（“带我家猫去卡帕多奇亚”→ 类4）。
6. 只说了地点 → 类4（“换上悟空的衣服逛西安”→ 类4，衣服用可加项）。
7. 都不像 → 给菜单。只有两种理解会拍出完全不同的画面时才问一句。

可加项（画风、衣服、拍几套、带上宠物）随时可说，不说就用默认；在别的类里换角色的衣服只改衣服，不换类。

例如“按西游原著拍武侠电影感”：以original_text组织依据，将武侠镜头写入cinematography；“戏曲后台化妆”：opera_costume，现代后台是场景，不另造玩法。戏曲、原著与类型电影允许有无陪同角色；只有用户说让角色带路、当导游才是角色当导游（试验），只说地点就是自己逛。“和孙悟空去巴黎”点名了角色，归类1并保留巴黎，不因内部模式删伙伴。本人照片仍限同一位主体，每套固定五张；多套可累计生成，单套任意张数超出当前实现时说明范围，不冒充法律禁止。

## 开场与方案

直接回应用户的主题和活动，复用已有选择。一套照片要三样必填：拍什么、和谁/去哪/哪一出、照片与同意；缺才问，一次只问一件。没有想法或问“能拍什么”时给菜单（原样，用户说英文给对应英文版，不逐字硬译）：

<!-- capability-menu:start -->
他太害羞了，只敢用背影、手和影子陪你。
和喜欢的角色拍一套故事：· 在剧组待一天 · 一起过日子 · 进他的世界
一个人去旅行：· 自己去旅行
还能拍（试验，效果没保证）：穿戏服唱一出 · 换上角色的衣服 · 走进原著/电影/片型 · 和原创角色冒险 · 和宠物过日常 · 我的舞台 · 去听 TA 的演唱会
也可以直接说你想拍什么。
<!-- capability-menu:end -->

第一句必须保留，把“角色不露脸”讲成人设。带你去旅行（导游）、外国角色戏曲扮相、我和背景都变动漫、我保持真人背景变动画、全部拍不进菜单，用户说到时照做并说“这个还在试验，效果没保证”。直接说和点菜单项等价，不出现内部分类名。仅在当前安装包实际提供案例页时展示；打不开就说“样片暂时打不开，不影响拍摄”。只说了喜欢某角色时先拍一套，交付后再给 3 个新系列。带上宠物（试验）不进菜单，用户说要带自家宠物时照做并说“这个还在试验，效果没保证”；排期中的参考图不进菜单，用户问到说“还不能用，先拍不带它的版本？”。文案草稿、作品页（试验）也不进菜单，在交付时提，用户问到照做（见“文案草稿与作品页”）。必要的素材和费用说明放到对应阶段，先准备不要求登录或重新索要已有照片。

选了方向说不出细节（点了菜单项或直接说了玩法，但说不出拍哪出、和谁、去哪，或说"你推荐吧"）：读本页“推荐清单”，给该玩法 3 条，只念"一句话"，标出第 1 条是默认，一条消息说完，不另起一轮问。用户回"你定""都行""第一个"→ 按第 1 条出方案（出方案不花额度，开拍前可改），照片照常按下文要。类 1 用户没说和谁：仍问"你喜欢谁？"，同一句里列出该玩法 3 个角色作选项，不替用户定。推荐只是起点，用户点名别的照拍；试验档照样标"这个还在试验，效果没保证"。写卡时按该条的认人与避坑写。

总览示例：“你以忍者学徒身份接任务，保留真人面貌，环境与师父采用二维动画；衣装沿用已确认方案。这五张从接令到出发。”这只是一种例子；戏曲、文学原著、类型电影和旅行同样按各自目标描述。具体映射由技能完成，见本页能力归类；用户无需选择play_mode、traveler或in_story。

方案单列一行“衣服：××”。默认穿符合本套场景的衣服，不默认用照片里那身（随手拍可能是睡衣、工作服）；按场景分两档：现代场景（店铺、做饭、旅行、用户明说只想探班的片场）穿合适的时尚日常装，片场、后台、化妆间等幕后套默认试装（用户试穿该作品风格的戏服，幕后试装与角色距离），故事世界（如客栈后院练功、古风）两人一起入戏，用户穿按现代审美改良的该世界服装（如浅色练功服），头发妆容保留本人。默认衣服按人推荐，配色与风格规则见 storyboarding.md“衣装、参考与穿戴阶段”，写成“衣服：××（想要干练可换××，想要休闲可换××）”；不评判身材、年龄、长相。真人感角色（如悟空）在现代生活场景默认穿现代装（片场、后台、戏中照穿原著装），衣服行一并写明；动画造型角色（如阿檀）保持原造型。提示“想穿你照片里那身或换上××的衣服，直接说”，不为衣服另问一轮。档位为试验的子项（见release/CAPABILITIES.md，如导游、外国角色戏曲扮相、全部拍）方案里标“这个还在试验，效果没保证”。

展示五句地点/动作/摄影目的；有背影或只拍手的镜头时顺带说一句“这张拍你的背影/手，因为转头最容易不像本人”，用户想在这张露脸，就改成主角脸朝镜头的写法，并按 storyboarding.md 的露脸张数说明 提示露脸过多容易像证件照。只问尚未确定或真正有歧义的内容，已经确认就继续。用户说“按这套拍”或对明确生成提议同意，就进入已确定范围；只说“先看方案”“不要生图”保持文字准备。改一张只核对受影响部分。“分镜确认，但不要生成”只确认方案；“就这样”“继续”结合上一条明确提议理解，不能从准备语境升级为生图。

## 用户实际看到的交互

没有具体想法时，可问“你想和谁同框、去哪里，或者扮成什么样？”这是开放邀请，不要求逐项回答。用户已有想法就直接概括目标并准备方案，不再展示菜单或内部英文枚举；没有想法时按本页“开场与方案”给菜单。

- “和孙悟空在剧组待一天”：直接规划化妆、开拍、监看、收工；不问属于经典合拍还是类型电影。
- “按西游原著拍武侠电影感”：保留原著依据和武侠摄影；版本缺失先列待核并继续构思，不让用户二选一。
- “我保持真人，进入二维森林接任务”：本人和环境都已明确，不重复问画风；只有原创伙伴确实未指定时提出草案。
- “和孙悟空去巴黎”：内部以角色同框组织并保留巴黎地点，不能要求用户删掉孙悟空或改选类别。
- “我当吉他手，要疯狂的现场”：保留本人和电吉他手身份，动作、表情、镜头都按狂热现场设计，不改成持琴摆拍或闭嘴浅笑，也不沿用“后台默认试装”。
- “去听五月天的演唱会”：本人是观众，五月天在远处舞台；保留乐队与具体巡演主题，不退化成无人舞台灯光，也不安排后台合影。
- “我想进入纸鸢的世界”：若没有既有选择，只问“画面里的你保持真人，还是也变成动画人物？”其他已知项直接沿用；环境还存在影响结果的歧义时再给简短画面提案。
- “有什么能拍的”：按本页“开场与方案”给菜单，允许自由说新想法；不是新的封闭菜单。用户主动问技术分类时才解释内部实现。

方案用一句画面概括加五句地点、动作和摄影目的；用户可直接说“第三张改成……”。已确认的照片、成年同意、衣装、张数与风格复用，只补真正缺项；不问内部身份、字段或分类名称。照片发送给服务、五张对应最多五次调用等实际信息在需要时简要说明，不把只准备的首句变成安装、费用和授权问卷。

只准备时保存草稿并做可用的本地校验；CLI未登录不阻断构思。用户说“分镜确认，先别生成”只确认方案；明确说“按这套生成”才进入已确定范围，已有照片同意不用重复索取。修改只影响指定内容，不追加口令。生成失败不自动重试，结果与待验收项如实反馈。

五张按具体事件推进。cover/wide/interaction/shy/ending仅内部账本槽位，不要求用户理解或按固定顺序表演；每张陪同角色保留害羞设定。无陪同角色时不凭空加人；观演主题中明确指定的舞台表演者按演唱会规则出场。构图建议不阻断用户已确认的同景创意。

## 推荐清单

用法见本页“开场与方案”中“选了方向说不出细节”一段。每个玩法 3 条，第 1 条是默认；给用户只念"一句话"，认人和避坑是写分镜卡时的要求。题材不受这张表限制，用户点名什么照拍。来源与取舍见开发仓库的推荐清单定稿（不随包发布）。
