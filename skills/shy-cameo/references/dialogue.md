# 对话与状态表达

## 多系列与返回用户

先读series-projects.md。老用户先说上次拍到哪、哪套还没定，问接着还是拍新的。只说喜欢孙悟空：先拍一套；交付后问“要不要接着拍？”并给 3 个新系列，用户选中的那套才加进selection；明确要后台/练功/美食三套：给三套分镜和共15张范围，不强迫只选一套。只准备就保存不提交；明确按三套拍就依序执行。返回时读取project-status，先说明哪套已拍、哪套待修改、哪套未提交。新系列不扩入旧selection。选版只更新索引，accepted仍依据真实用户反馈和record-verdict。

## 开场与方案

直接回应用户的主题和活动，复用已有选择。一套照片要三样必填：拍什么、和谁/去哪/哪一出、照片与同意；缺才问，一次只问一件。没有想法或问“能拍什么”时给菜单（原样，用户说英文给对应英文版，不逐字硬译）：

<!-- capability-menu:start -->
他太害羞了，只敢用背影、手和影子陪你。
和喜欢的角色拍一套故事：· 在剧组待一天 · 一起过日子 · 进他的世界
一个人去旅行：· 自己去旅行
还能拍（试验，效果没保证）：穿戏服唱一出 · 换上角色的衣服 · 走进原著/电影/片型 · 和原创角色冒险 · 和宠物过日常
也可以直接说你想拍什么。
<!-- capability-menu:end -->

第一句必须保留，把“角色不露脸”讲成人设。带你去旅行（导游）、外国角色戏曲扮相、我和背景都变动漫、我保持真人背景变动画、全部拍不进菜单，用户说到时照做并说“这个还在试验，效果没保证”。直接说和点菜单项等价，不出现内部分类名。当前版本没有案例页，不提；案例页随包上线后本句改为首次给菜单时打开，打不开就说“样片暂时打不开，不影响拍摄”。只说了喜欢某角色时先拍一套，交付后再给 3 个新系列。带上宠物（试验）不进菜单，用户说要带自家宠物时照做并说“这个还在试验，效果没保证”；排期中的参考图不进菜单，用户问到说“还不能用，先拍不带它的版本？”。文案草稿、作品页（试验）也不进菜单，在交付时提，用户问到照做（见“文案草稿与作品页”）。必要的素材和费用说明放到对应阶段，先准备不要求登录或重新索要已有照片。

选了方向说不出细节（点了菜单项或直接说了玩法，但说不出拍哪出、和谁、去哪，或说"你推荐吧"）：读recommendations.md，给该玩法 3 条，只念"一句话"，标出第 1 条是默认，一条消息说完，不另起一轮问。用户回"你定""都行""第一个"→ 按第 1 条出方案（出方案不花额度，开拍前可改），照片照常按下文要。类 1 用户没说和谁：仍问"你喜欢谁？"，同一句里列出该玩法 3 个角色作选项，不替用户定。推荐只是起点，用户点名别的照拍；试验档照样标"这个还在试验，效果没保证"。写卡时按该条的认人与避坑写。

总览示例：“你以忍者学徒身份接任务，保留真人面貌，环境与师父采用二维动画；衣装沿用已确认方案。这五张从接令到出发。”这只是一种例子；戏曲、文学原著、类型电影和旅行同样按各自目标描述。具体映射由技能完成，见routing-and-journey.md；用户无需选择play_mode、traveler或in_story。

方案单列一行“衣服：××”。默认穿符合本套场景的衣服，不默认用照片里那身（随手拍可能是睡衣、工作服）；按场景分两档：现代场景（店铺、做饭、旅行、用户明说只想探班的片场）穿合适的时尚日常装，片场、后台、化妆间等幕后套默认试装（用户试穿该作品风格的戏服，D23），故事世界（如客栈后院练功、古风）两人一起入戏，用户穿按现代审美改良的该世界服装（如浅色练功服），头发妆容保留本人。默认衣服按人推荐，配色与风格规则见 scene-card D22，写成“衣服：××（想要干练可换××，想要休闲可换××）”；不评判身材、年龄、长相。真人感角色（如悟空）在现代生活场景默认穿现代装（片场、后台、戏中照穿原著装），衣服行一并写明；动画造型角色（如阿檀）保持原造型。提示“想穿你照片里那身或换上××的衣服，直接说”，不为衣服另问一轮。档位为试验的子项（见release/CAPABILITIES.md，如导游、外国角色戏曲扮相、全部拍）方案里标“这个还在试验，效果没保证”。

展示五句地点/动作/摄影目的；有背影或只拍手的镜头时顺带说一句“这张拍你的背影/手，因为转头最容易不像本人”，用户想在这张露脸，就改成主角脸朝镜头的写法，并按 scene-card D25 提示露脸过多容易像证件照。只问尚未确定或真正有歧义的内容，已经确认就继续。用户说“按这套拍”或对明确生成提议同意，就进入已确定范围；只说“先看方案”“不要生图”保持文字准备。改一张只核对受影响部分。“分镜确认，但不要生成”只确认方案；“就这样”“继续”结合上一条明确提议理解，不能从准备语境升级为生图。

## 照片与参考

拍什么一确定就要照片，一条消息说完：“发一张清楚的正脸照。是你本人，还是已同意的成年人？照片只存在你电脑里，会发给生图服务。照片里的人如果不是你，请先告诉对方要做什么，并取得对方单独同意。”用户说“先不发、先看方案”→ 衣服用场景默认，开拍前再要；同一张照片之后复用。照片若在方案后才到且影响衣服推荐，先说“按你的照片，衣服建议改成××”，用户同意再改。一张就能拍；多给侧脸是否更像尚未对照，不承诺。已有同一张照片（按内容比对）且同意记录有效就沿用，不重复索取；换了照片重新问。体检发现格式损坏则换有效文件，不花额度；检测器缺失说明人工核对，不能当作照片质量通过。说明实际发送的参考清单，不把网页查资料说成传入实景图。

用户给一张氛围图说"照这个感觉拍"：说"图里的光线和色调直接带不过来，我看图后用文字把它的光写进去"；自己看图，用一两句写出主光方向、冷暖和明暗，写进 lighting 与 cinematography，不写 mood_ref、不把图发给生图服务；图来源说不清或图里有未成年人 → 不看图，按下一段选光线风格。
带上宠物（试验）：要宠物照时说"给一张它清楚的照片：它占满画面、睁着眼、看得见全身；有不同姿势的也可以一起发，我挑最清楚的那张用"，目前只用其中 1 张（多张同时参考还没做）；先问"这是你自己的宠物吗？照片会发给生图服务"，确认后用 consent 登记，写进套图卡 `pet`（ref＋kind，如"猫"）；封面必有宠物，默认五张都有它，剧情说得通才空一张；它是来陪你的，用户没说时问一句"它平时更爱被抱着，还是跟着你跑？"，按回答定陪伴方式（写法见 scene-card.md"带宠物的套图"）；照片里有人手、杂物没关系，不会画进去；它在照片里只占一小块时，裁成只剩它的特写再用（告诉用户"我把照片裁到只剩它"）；照片里有别人的脸 → 请换一张或裁掉。说"效果没保证"。
和宠物过日常（试验，菜单项）：要宠物照与授权同"带上宠物"；看图认出品种体型后确认一句（"它是英短金渐层、偏胖对吧？"）；问"它平时最爱干什么？比如踩你、钻箱子、趴窗台、守着你吃饭"，按回答编一件小事的 5 张；说不上来时按体型给 4 个题材——猫：窗边看雨、周末赖床、钻纸箱搬新家、深夜陪加班；小型犬：周末赖床、出门买早餐、等你下班开门、窝沙发看电影；大型犬：清晨公园遛弯、湖边玩水、露营篝火、雪天第一次撒欢。画面里只有你和它；有人要加角色 → 改走"带上宠物"＋对应玩法。
用户只说"要电影感""要有氛围"、说不出要哪种光时，不让用户自己去找参考图：先从本项目已有成片里挑 4–6 种光线风格（如单灯夜景、冷暖对撞、舞台聚光、烛光暗调、蓝调时刻、高反差布景）拼成一张图给用户选；还没有成片时各用一句话描述让用户选，选中的写进 lighting 与 cinematography。用户自己给的参考图本身不是电影感的（手机随手拍、平光、灰平）不借，直说"借过来会更像手机照"，改从上面的风格里选（2026-10-28 用手机拍的猫照当氛围照，成片灰平）。

## 开拍与等待

开拍说明与开始生成在同一条回复，只告知不再确认：“这套5张，每张提交算一次额度，最多5次；第1张失败就停，后面不花。通常6–12分钟。”多套写总数，如“共4套20张，最多20次额度，大约半小时到一小时”，并说明每拍完一套会停下给你看，回“继续”才拍下一套。Codex里每张出来报一句画了什么；Claude Code按stderr进度报“第2/5张…”，每套结束用系统看图打开。叫停用宿主停止按钮或Esc，正在拍的那张可能已算额度。交付时一句话问：“像你吗？角色和感觉对吗？哪张怪或想改直接说。”没答到且记录需要的项，追问一句，不替用户填；任一项答“否”即记rejected，“这套想要的感觉拍出来了吗”一项的回答用record-verdict --goal记录。选旧版、重拍某张都在交付这一步（选版只更新项目索引selected_run_id，验收用record-verdict），不进下一套。

## 失败与中断

说明哪张已提交、哪张未提交、实际返回什么；额度可能计入，不声称已查账单。首张失败取消后四张；中间失败保留其他已授权张，不自动重试。

**内容审核拒绝后的恢复**：先用一句易懂的话说明哪张没有出图、服务返回的实际类别，其余已出图片仍保留；原始错误与request ID留在私有记录。依据记录中明确提供的输入或输出审核阶段说明，未提供时不猜；“具体触发原因未知”不抹掉已经提供的审核阶段。不把猜测说成原因，也不把正常衣装或用户审美偏好一概称为违规。

保留用户可接受的创作目标，主动提出一个内容上确实不同、符合要求的安全替代画面，而非只留下缺图让用户自己解决。例如陪伴套图可用猫与抚摸手的桌面特写，衣装仅由袖口保持连续，不继续描绘原被拒画面的身体构图。说明改变了什么、保留了什么；不能通过同义词、删标签、隐去意图或更换服务重现被拒内容。用户若要求保留原被拒内容并绕过审核，不执行。

新方案符合用户已授予的修改范围与调用上限时，可作为独立新请求执行，不重复索取已有授权；否则先给具体备选，只补真正缺失的选择或授权。余额本身不等于授权。旧拒绝请求保持rejected，新方案另存实际内容、引用与结果，不复用或重置旧账本、不自动恢复首图失败后取消的镜头。新方案再被拒就停止，不形成替代方案循环。返回图片后核对故事作用、主体、衣装连续性及构图；补齐候选不等于用户验收，也不承诺零拒绝率。

**拍摄中的停顿**（本套没拍完，继续 = 拍完这一套）：
- 封面机器比脸偏低（set_paused_likeness）：给用户看封面；说像 → `--resume` 续拍本套；说不像 → 改方案另起一套。
- 结果不确定（set_paused_unknown）：先核对set-status与调用记录，按实际set-record，再续拍本套未提交的张（Claude Code 用 generate-set --resume，Codex 按未提交的张逐张 compile-shot→原生生图→set-record）；不猜失败，不自动续跑。
- 比脸不可用（unavailable）：照常拍完，交付时说明这次没做机器比脸。
- Codex路径没有自动暂停：封面出来后宿主跑likeness-check，结果按上面同样处理。

**接着拍新一套**（继续 = 下一套）：本套已交付后问“要不要接着拍？”并给 3 个新系列；用户选了哪套，就把那套加进项目selection，再`project-continue`登记后回到方案。用户说“全部拍”（试验）：一条消息列出几套各拍什么、总张数与时长，仍每拍完一套停下，回“继续”再拍下一套。

**文案草稿与作品页（试验）**：一套交付后，在问“要不要接着拍？”同一条消息里加一句“需要的话我写一份发帖文案草稿（纯文字）”；不主动直接写。用户要 → 写一份：一句标题＋3–5 行正文＋3–5 个话题标签；用“他太害羞了”的人设口吻，可带“猜猜今天来客串的是谁”和彩蛋线索（只指向图里有的背影、手、道具）；跟随用户语言；不写真人演员名、不写现代作品的影视版本；末行固定“（图片由 AI 生成）”。写完存 `WS/captions/<set_id>.md`（UTF-8；同名旧稿先说“会替换上一份”），在对话里贴全文，并说“发布及 AI 生成声明由您自行负责”。不代发、不碰账号、不讲平台操作；用户改稿只改文字，不重拍。交付一套后或用户问“拍过的在哪 / 给我看看”时，跑 `CLI gallery --workspace WS`，给出 `WS/gallery.html` 路径，说“页面只用来看，选哪一版、接受或重拍在这里说”。

## 检查与验收

先自己看人体、角色、本人/环境表现、动作和摄影目标，再请用户逐张确认本人感、角色与异常以及本次目标是否满足。用户已经明确接受的范围如实记录，不要求固定口令；没有反馈保持pending。电影感、原著还原和真实机位各有自己的证据，不能用一个“看起来不错”替代。

## 审计

- pass：在限定调用窗口中参数与参考一致且只有一次可识别调用；不证明服务商账单、成片视觉质量或输出来源端到端自动核实。
- unverified：本次无法可靠关联调用；保留候选及限制说明，不自动说“完全可用”或一律拒交。
- tampered：在可核对窗口中发现不一致或多次调用，保留原始记录与原因，不自行修改为pass。

## 未验证与创作范围

未验证不等于禁止；不因国别、作品年代或虚构年龄一概拒绝。平台实际拒绝原样说明，不改词绕过。害羞不露脸是创作设定，不是法律许可方法。实际权利问题见rights-cplus.md，不另造类别禁令。
