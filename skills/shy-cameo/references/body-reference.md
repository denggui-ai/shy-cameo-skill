# 身形参考与确认

## 未下载图库时

默认安装只带文字说明和索引，图片与 `body-reference/compare.html` 是可选附件。它们不存在是正常状态，不报错、不阻断策划或拍摄，也不要求用户先下载。直接按本人照片可见部分与用户的文字自述描述身形；只问当前画面缺少且影响结果的信息，允许保留未知。

用户想看参考图时，说明可以从[项目对应 Release](https://github.com/denggui-ai/shy-cameo-skill/releases) 手动下载 `shy-cameo-body-reference-20261102.zip` 与 `.sha256`，校验后解压到本技能的 `references/`，恢复 `body-reference/images/` 与 `body-reference/compare.html`。附件尚未发布或用户不想下载时继续文字沟通，不自动下载或生图补库。安装与缺图提示不构成生图授权。

只在比较页和本轮所需图片都存在时进入下面的看图流程；缺少某张时如实说明并沿用自述，不把缺图当作卡片或生成错误。用户的身形选择只记在私人工作区，不写入公共索引。

开发图库，五类照片见 `body-reference/manifest.json`，单项示意、体量、穿衣胸部及组合验证见 `body-reference/expansion-manifest.json`。两份索引共同决定当前完整性。五类是服装语境的近似轮廓，不是人体诊断、优劣或穷尽分类。只展示索引中 `visual_review` 为 `passed` 且文件存在的图；`user_verdict` 单独记录，目视通过不等于用户已接受。缺图明确说明，不补标签、不拿失败图当标准，不自动调用生图补库。

## 使用流程

选图默认展示写实穿衣模特照片，示意图只辅助解释局部关系。首次比较整体轮廓时，打开`body-reference/compare.html`，将 B01–B05 五张正面同组展示（桌面横排、窄屏横滑），不要拆成多轮或用五张纵向大图代替同组比较。若宿主打不开页面，先明确说明并提供完整五项可访问的图片入口；某图未显示时重新展示，不把发送成功当作用户已看到。用户可选编号、组合局部或说都不像；选中后按需展开侧/背面。整体轮廓用全身图；穿衣胸部量感优先用头顶到腰/上髋的上半身图，先展示同模特同服装的三张正面，拿不准再补相关侧面。T01/T02/T03分别为较小、适中、丰满，使用`-front`与`-side`；只展示已通过且文件存在的项，未齐全时说明，不用旧图冒充新组。统一合身浅方领可帮助观察，但不能用胸沟深浅、露肤多少或聚拢效果代表大小，更不能映射罩杯。

1. 看照片可见范围和当前镜头。清晰全身照支持的轮廓直接参考；半身照可参考可见的穿衣后肩胸腰轮廓，不推断衣下尺寸或未入镜臀腿。已有清楚自述直接沿用；当前镜头用不到的信息无需追问。
2. 缺失且影响画面时，用开放、具体的一句话询问当前最关键的缺失特征；先问用户实际身形，不能把“你属于哪种”变成默认改形或用“直筒/曲线”二选一概括全部臀腿。用户不知道或想看图时，除五类整体轮廓同组比较外，每轮默认最多展示四项相关参考；不要求测量、上传私密照片或选专业标签。肩腰髋横向关系看正面/背面；腰腹和臀部前后轮廓看侧面。用户只要背影时，不因胸部看不到就追问罩杯。
3. 用户可选编号、组合局部或说都不像。选图用于沟通，不证明本人实际尺寸；无法选择时允许描述差异或保留未知，不强迫归类。用户说“你决定”时记录为暂定呈现，不记为本人身体事实；个性化预览仍需已有生成授权。
4. 确认的轮廓与补充写入现有 `user.action` 描述，衣装写 `outfit/costume`、机位写摄影描述；不新增 Schema。私有工作区记录图号、可见范围、用户原话、修改边界、参考来源及实际接受状态，不将私人选择写入公共图库。
5. 本人照片仍用于身份；图库只提供已选的轮廓依据。选择沙漏或梨形不自动决定胸臀大小、身高、肌肉量、腿长或性感风格。正式写真遵循用户保留真实身形或明确调整的范围；已确认内容不重复问。

## 五类与固定编号

| 编号 | 名称 | 主要可见依据 |
|---|---|---|
| B01 | 沙漏形 | 肩髋接近，腰线明显收窄 |
| B02 | 梨形 | 髋比肩宽，下半身轮廓较突出 |
| B03 | 倒三角形 | 肩比髋宽，上宽下窄 |
| B04 | 矩形 | 腰侧收窄较少，整体较平直 |
| B05 | 苹果形 | 腰腹相对丰满，腰线柔和；结合侧面观察 |

每类使用 `front`、`side`、`back`，文件名为 `B01-front.png` 等。五类可与丰满程度、肌肉表现和比例组合；这些不随类型自动赋值，不根据照片推断健康或体脂。

按缺项选扩展参考：D01为简化肩腰髋关系；D02为体量；D03为相对身高；D04为腿身比；D05为穿衣胸部轮廓；D06为臀部侧面突出。M01–M03是体量照片；T01–T03是上半身穿衣胸部量感照片。C01–C03旧全身胸部图已归档，不再作为选项。示意图只解释一个维度，不作人体比例或测量标准；一张含多个选项的示意按选项数计入每轮最多四项，五类整体轮廓首次选图可同组展示五项，其余维度继续按需展开。X、W编号用于开发组合/换装验证，已从用户选图入口归档；不将失败组合混入图库或用成功个例承诺任意组合可控。

## 身体、穿衣与画面分层

分别记录不等于人体参数完全独立或模型能精确控制。整体轮廓、整体体量、身高、腿身比例、骨架与肌肉外观、局部轮廓可组合；不将它们做成互斥的单一分类。高个不自动长腿，纤细可以局部丰满，矩形可以整体丰满；臀宽与侧面突出程度分别表达。未知字段不填默认“标准身材”。全身入镜但宽松衣服遮挡的部位仍未知。

胸部仅按需描述穿衣后量感、侧面突出和可见饱满分布；间距、位置、不对称有依据且当前需要才记录，不推断衣下形态。水滴等名称保留用户用语并补可见描述，不当医学分类。罩杯是可选自述，保留完整原话及已知品牌/体系；单个字母不映射固定体量，不从图猜罩杯，不自动跨体系换算，不要求普通写真用户测量。

衣装单独说明已知的版型、贴合、厚薄、垂坠、支撑/塑形效果，不猜具体内衣。姿势与摄影另写其字段。显腰细、显腿长优先用穿搭和摄影；“胸更丰满”若衣装表现和身体改变会得到明显不同结果才澄清。翘臀不自动加臀宽；性感是造型偏好，不自动改胸腰臀或体量。

沿用已确认且本次未修改的身体基准；当前明确调整仅覆盖对应部位。新旧描述冲突且影响画面时问一句，照片与自述不同先考虑服装和摄影影响，不直接否定用户。改形另记版本和变化范围；未接受生成图不能升级为默认身体事实。换衣后的轮廓差异先检查衣物、姿势与镜头，不一概判定身体漂移。

私有记录分开写：照片可见事实与条件、用户自述、期望调整、未知项、生成观察、用户接受状态。将本张需要的已确认基准和调整边界写入`user.action`，不要把未知项自动补成生成约束；图库模特只作沟通，不塞入用户身份照片槽位。比较图可引用局部关系，不继承模特脸、衣服或所有身体属性。编译后核对实际请求与参考输入，不能只确认对话正文。

## 验收与组合

分别判断目标轮廓是否可见、未要求改变的身体是否漂移、衣服是否合理合身，以及姿势/摄影是否制造了差异。遮挡不可判断，不根据提示词或尺码标签宣布通过；用户接受与视觉检查分开。多维组合只需按当前需求生成，不枚举所有组合，也不以图库张数证明人群覆盖率。
