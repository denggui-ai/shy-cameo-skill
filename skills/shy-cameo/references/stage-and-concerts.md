# 我的舞台与去听 TA 的演唱会

两个玩法均属试验：单张 POC 或方向认可不等于五张整套、歌手辨识与本人感均已验证。先看方案不需要照片或生图登录；确认后生成、失败和中断处理沿用主流程，经典观演的顺序与替代范围见下文。

## 先确定谁在台上

- **我的舞台**：本人当主唱或乐手，投入自己的演出。`play_mode=my_stage`，`user.mode=in_story`，`user.role` 写实际身份，如主唱、电吉他手、架子鼓手、贝斯手、键盘手；`characters=[]`。本人保持自己的脸，不默认扮成某位明星；舞台服装按用户偏好设计，不把乐手统一写成歌手。
- **去听 TA 的演唱会**：本人是观众，TA 是台上的歌手、乐队或虚拟歌手。`play_mode=concert_audience`，`user.mode=traveler`，`characters=[]`；用每镜的 `performance` 写演出者。可以点名现实艺人，不套用旧的“真人歌星连背影也不画”。

已明确谁表演就直接准备；只说“演唱会”且身份不明时才补问。用户同时想拍两种，分别准备两套，不在同一套里把本人忽然从观众变成歌手。未指定巡演时可以先提一个明确版本，不把年份、歌曲与衣装混成不存在的纪实记录。

## 五张要有经历

以下是起点，按用户创意改写，不固定每张照抄：

| 玩法 | 五个事件 | 衣装和摄影重点 |
|---|---|---|
| 我的舞台 | 开场的第一个重拍 → 投入演奏或与队友合奏 → 乐器细节 → 独奏/合唱爆发 → 最后一个和弦或共同谢幕 | 不强制从安静候场开始；一至两张清楚可辨的表演镜头，其余按动作需要选背影、手部、远景；整套同一身份与乐器 |
| 去听 TA 的演唱会 | 入场期待 → 从观众区看到舞台 → 应援细节 → 跟唱或安可 → 散场回味 | 本人穿观演衣装，按故事安排露脸；看到舞台用本人背影/越肩，不能同时要求本人正脸朝镜头又面对身后的舞台；经典场次用下方五张方案 |

本人始终是故事主角。别把五张都做成举荧光棒的同一姿势，也别让艺人近景占满画面。观演套在合适的镜头保留可辨识的舞台表演者；入场、手部特写、散场可以不出现TA。历史演出明确写成想象中的观演，不宣称用户实际到过现场。

## 观演物料与动作

策划观演时，和衣装一起考虑适合本场的门票、场刊、应援用品或巡演周边。按艺人、年代、场次、歌迷文化及用户偏好选择，通常一两件就能串起故事；不是必带套餐或数量上限，用户指定空手或自带物料时沿用。应援棒、手幅、毛巾、小卡、巡演T恤、徽章、头巾、海报和周边袋只是候选，不把现代应援方式默认放进所有历史摇滚现场。

物料要带来具体动作与前后变化。例如入场时拿纸票，现场特写里一手捏着检票后留下的票根、另一手搭栏杆，散场后把票根夹进场刊再收好；检票形式与物件外观按所选场次核对。也可围绕已选应援物或新买的纪念品设计别的经历，不将“票根＋场刊”固化为每套模板。舞台凝望与合唱镜头可以空手，物料不必每张入镜；物料的取得、使用与收纳要连贯。

具体官方款式、年份或图案有依据才称还原；缺证据时标为创作选择或待核，不用其他地区、年份的商品冒充当场售卖物。写清物料在本镜的状态与手部动作，沿用现有 `props`、`user.action` 等字段；持握、承托与连续性按 [道具选择、搭配与状态](storyboarding.md#道具选择搭配与状态) 处理。露脸镜头可拍拿着纪念品离场或收好票根后的反应，让表情跟着事件走，避免入场和散场都只是站定浅笑。

## 经典观演：五张分镜与顺序

经典场次默认用两张舞台、三张个人经历，锁定同一场演出、对应歌曲时刻、当场造型与同一套观演衣装。用户已有明确分镜时沿用。先核对所选版本，未知处明说；不把不同年份的服装、乐器和舞美拼成纪实记录。

| 故事顺序 | 画面与故事作用 | 本人 / 演出者 | 执行编号 |
|---|---|---|---|
| ① 入场期待 | 走进场馆通道，可拿着本套选定的门票或场刊，半身侧正脸，听见场内声音的期待；认清主角 | face / 不入镜 | 2 |
| ② 终于看见 TA | 从本人肩后看舞台，本人背影在前景，选定场次的艺人造型、乐器与演出瞬间可读；整套核心 | back / 入镜 | 1 |
| ③ 身在现场 | 围绕选定物料拍手部动作，如一手捏票根、另一手搭栏杆；也可空手感受舞台反光，袖口衣装连续；收进个人感受 | hands / 不入镜 | 3 |
| ④ 全场高潮 | 比②更宽的观众区，本人举臂加入合唱，远处舞台表演与人群呼应；改变动作和景别 | back / 入镜 | 4 |
| ⑤ 散场余韵 | 收好票根、拿着场刊或纪念品离场等与本套有关的结束动作；无物料时按原故事收尾。身体与镜头关系自然，脸清楚，带着唱完的疲惫与兴奋 | face / 不入镜 | 5 |

**先生成②，再生成①③④⑤；交付按①②③④⑤。** 核心图占五张中的一张，不额外试拍。先拍它是为了尽早检验核心内容能否成立，不是绕过审核的探针；通过不保证后续一定通过。

写卡时 `shots` 按执行顺序放 `[终于看见TA, 入场期待, 身在现场, 全场高潮, 散场余韵]`，套图另写 `story_order: [2, 1, 3, 4, 5]`，表示按哪些执行编号展示故事。`compile-shot` / `set-record --index`、请求、账本及项目候选始终使用执行编号；CLI 返回的 `story_index` 和作品页才用故事编号。用户说“第①张入场”时先按卡片映射到执行编号2，不能重拍成舞台图。旧卡省略此字段即保持原顺序；不重排已提交的旧 `shots`。

执行第1张仍作本套首图参考：核实失败就取消余下四张，未知结果保持 claimed；停止时仍结束整个进程组。它是背影时不跑露脸封面的自动比脸，不能说本人感已过机器检查；后续露脸镜头仍使用原始身份照并目视核对，不从背影首图推断五官。`performance.visible` 在执行编号1、4为true，其余为false，不因首图有艺人就带到入场、手部或散场。

## 审核拒绝：保留故事作用的一次替代

方案里一并写清可接受的替代内容和调用上限，沿用已有授权，不另加固定口令：默认最多5次、按实际成片交付，不自动补图；只有用户明确允许一次观众故事替代时，才将**原请求与替代合计上限设为6次**。五次或六次都不保证得到五张图，也不保证替代通过。余额、方向认可或连接错误均不等于补图授权。

| 实际结果 | 处理与替代画面 |
|---|---|
| 核心②（执行1）被拒 | 停止原套，保留rejected与后四张cancelled。接受观众故事版且次数足够时，用新set_id和新卡：②改为舞台亮起时本人的反应，④改为本人投入跟唱，两张均不出现艺人或可辨识替身，整套命名为“观演故事”。新方案可把两张露脸放在②④，尚未拍摄的①⑤改为入场/散场背影，并说明此调整。先生成替代②，成功后才拍其余四张；原1次＋新套最多5次＝总上限6次。不能恢复旧cancelled或宣称经典现场复刻完成。 |
| 核心②成功、高潮④被拒 | 保留成功图，原套其余已授权镜头按常规规则处理；有一次补图授权时，把④另建为本人跟唱近景，舞台艺人不入镜，以反应保住高潮。既有两张露脸时，此补图可成为第三张，作为已批准的替代例外，不为凑1–2张再重拍成功图。 |
| ①③⑤等其他镜头被拒 | 不套用舞台替代模板；按实际拒绝内容提出实质不同且承担相同故事作用的画面，不能只换词或挪一张散场照填高潮。超出既有替代范围才补问选择。 |
| 超时、连接错误或没有可核对的图 | 保留claimed并停止核对；不记审核拒绝、不直接补交。 |

替代改变的是可见内容：演出者及可辨识替身不入镜，不用缩远、遮脸、删姓名或换服务重现被拒画面。新卡保留实际演出主题作背景信息，但 `performance.visible=false`，不复制原表演造型、舞步或舞台构图到可见描述；不承诺任何姓名或题材必过。若用户只接受指定艺人的名场面，观众反应不能等价替代，应停下交付现有结果或另选题材；原创乐队属于换题材。

在私有工作区的拍摄记录保留原set_id/执行编号、拒绝类别和request ID、已授权替代范围、总次数、实际提交数、新卡与新请求的关联。每次提交前合计旧请求和替代请求，不借新set_id重置总上限。这是宿主流程核对，不宣称现有CLI提供跨请求的六次硬拦。

一次替代被拒就停止本轮，不再改词或开第二个替代；替代结果未知也停下核对。核心失败后的新观众故事采用逐张路径，确保新一轮再次拒绝时立即停，不交给自动跑完整套的批处理。Codex用 `compile-shot → 原生生图 → set-record`；Claude Code可用 `compile-shot → generate-exec --authorized-count 1 → set-record`，每张读实际结果再继续。替代首图若露脸，两条路径仍按generation.md执行 `likeness-check`：分低先等用户比脸，不可用则如实说明。原套未提交的记录始终保留。

只补④时，按 **单张 `compile` 形成新请求 → 将新 `run_id` 与实际 `scene_card` 保存到原套执行编号4的 `shots.candidates` → 提交生成** 执行。候选保存完成后才提交，确保提交后中断仍能找到这次尝试；登记时保留旧拒绝与当前 `selected_run_id`。`compile` 可用原套 `--chain-set` 维持衣装，卡内明确演出者不入镜；索引写法见[重拍与选版](series-and-projects.md#重拍与选版)。返回图后检查故事作用、本人、衣装及构图；用户选用才更新项目 `selected_run_id`，逐张验收仍独立记录。补齐候选不等于整套accepted。

## 我的舞台：乐手与狂热现场

用户希望疯狂、放开时，把演奏、情绪和摄影一起放开。可以用汗水、飞起的发丝、绷紧的琴带、扫弦的手臂、震动的镲片、灯束和观众响应构成现场感；不是只在背景加烟雾和激光，人物仍站着浅笑。已有温柔弹唱、古典或其他明确选择时沿用，不强制所有音乐都摇滚化。

| 身份 | 可读的爆发动作 | 必须成立的结构 |
|---|---|---|
| 主唱 | 张嘴唱出高潮、身体前倾或挥臂带动观众 | 话筒和手不挡关键五官，头颈自然连接 |
| 电吉他手 | 扫弦、推弦、弓步压低重心、独奏时上身发力 | 琴带承重，按本套确认的左右手习惯分配按弦与拨弦；琴颈、指板、琴桥连接连贯，不能反手绕背 |
| 鼓手 | 连击或重击后鼓棒弹起、镲片余振、身体随节奏发力 | 正常坐于鼓凳，手各持一根鼓棒，落点对应鼓面/镲片，手臂不穿鼓组 |
| 贝斯手 | 宽站姿随低音起伏，拨弦手发力、按弦手移动把位 | 按本套确认的左右手习惯演奏，贝斯比例、琴颈连接、琴带和两手职责正确，不自动换成六弦吉他 |
| 键盘手 | 身体前倾投入弹奏、双手分区触键、高潮时抬眼回应观众 | 键盘支架承重、按键方向正确；抬起的手不同时写成正在按键 |

五张有强弱变化，但不强制塞入两张安静照片。用低机位、近距离、适量斜构图、反差舞台光和局部运动拖影表现冲击；动作主体、关键手部与乐器结构仍可读，不能全图糊掉。一张抓一个明确瞬间，不同时写跳起、跪地、甩头、弹琴、举手五个互斥动作。

保留一至两张本人清楚可辨的镜头，它们也可以有张嘴、露齿、汗水和投入表情。主角头向按本镜创意；常规写真中的闭嘴浅笑、约20°转头和只拿轻便道具的建议不覆盖这些已选舞台动作。保留的是本人脸型、五官关系和身体结构，不是自拍里的安静表情。真人大动作与强表情的相似度尚未实拍验证，交付时分别检查，不为守“像本人”默认取消表演。

### 乐器结构与跨镜连续性

在分镜中确定每位吉他手或贝斯手的持琴习惯，沿用用户选择；未指定时可在方案中明确一种，不新增固定问答。把按弦手、拨弦手写入 `user.action`，把对应乐器、持握与肩带支撑写入 `props` 或 `prop_specs`。左右指该乐手自身的左右，不是画面左右；换成正面、背面或越肩机位时，琴颈在画面中的方向可以变，双手职责不随镜头翻转。提交前核对动作与摄影描述是否相容：常规右手拨弦、左手按弦的正面镜头，琴颈通常向观者右侧伸出，背面则相反；斜拍按实际姿态与透视判断，不能一边指定按弦手，一边强制矛盾的画面方向。停奏示意、谢幕等按本镜动作释放相应手，不能同时要求该手演奏。

按本套已确认的乐器型号核对弦数，并检查可见琴弦、琴枕弦槽、调弦机构与琴桥弦鞍是否对应；例如本套选了四弦贝斯，就不能用三弦或仅三组对应机构代替。其他明确选择的弦数按原方案，不一律规定所有贝斯四弦。背面、裁切或遮挡看不清时记未验证，不凭提示词写了“四弦”或琴体像贝斯就判通过。

吉他与贝斯的琴颈、指板、琴体及琴桥应在透视下合理连接，琴弦沿可演奏的路径延续至琴桥，不能在琴身上无故折向或错接。合奏中分别追踪每人的手、琴颈、琴体与肩带；画面投影交叉不等于穿插，应按可见遮挡和接触判断。保留已选的强动作与局部运动模糊，关键连接被遮挡或糊掉时记未验证，不能据此宣称结构正确。

后续串联只沿用首图中正确、可见且本镜需要的外观。若首图已发现镜像持琴或结构错误，在尚未提交的分镜中明确保留项与纠正项，并重新编译保存实际请求；纠正项优先于“与首图一致”，不改写已提交卡、请求或旧图。现有参考路径与调用次数规则照常适用，不额外生图或自动重拍。文字纠正不能保证图像模型忽略参考缺陷：每张返回后仍按人物自身左右、手与乐器接触、琴颈至琴桥连接逐项目视并跨图比较，未改善就如实记录，不以整体效果认可代替结构检查。

## 我的舞台：队友互动

策划乐队现场时，把“我与队友如何一起完成演出”作为分镜选择。通常可在五张里安排一至两张互动，与个人演奏、细节和全场镜头形成变化；这是可调整的建议，不要求每套凑数或每张多人。用户明确要独奏、单人舞台或队友不入镜时沿用，不额外加人。

| 音乐时刻 | 可选互动 | 拍法与动作关系 |
|---|---|---|
| 两个声部接上 | 电吉他手与贝斯手背靠背合奏，或侧身靠近回应一句旋律 | 主角占主要画面，队友背影或侧后方；两把乐器各自有琴带和持握，不让琴颈交叉穿身 |
| 进入下一段 | 主角回头点头回应鼓手，鼓手在鼓凳上接一个重拍 | 用越肩或侧后机位交代视线与空间；主角不露脸时不要求看见回头的脸。举手示意要选停奏间隙，不能同一只手又举起又拨弦 |
| 主唱与器乐呼应 | 主唱侧身把节奏交给吉他手，或键盘手抬眼回应主角 | 一张抓一个交接瞬间，写清谁在唱、谁在弹，主角身份与乐器不随镜头改变 |
| 演出结束 | 主角与队友面向观众共同鞠躬或举手致意 | 琴由肩带承托、话筒归位；鼓手离开鼓凳须发生在停奏后，不把谢幕写成仍在打鼓 |

队友默认是原创成年乐手，不拿某位明星的身份作替身；外观与乐器在再次出现时保持连续。队友可在近旁或中景，不一律退到远景，仍以背影、侧后方自然藏住五官，不用正面无脸人形。主角始终是故事与视觉中心，不把五张改成乐队证件合照。可有背靠背等真实配合，但两人的肢体、乐器与支撑分别成立。

沿用 `setting` 写队友位置和本镜是否入镜，`user.action` 写主角的动作及队友回应，`props` 写各人的乐器、持握与状态，`cinematography` 写主次与藏脸机位；仍为 `characters=[]`，不填 `performance`，不新增队友身份照片或定妆调用。后续单人镜头明确队友不入镜，不从链图继承人物。这一互动许可只用于“我的舞台”；观演中的真实艺人仍在远处舞台，不扩成同台或近距离合影。

## 选谁：认人依据要组合使用

独唱和乐队都支持。先看用户偏好；没有偏好时给可改的候选。以下是策划判断，不是已验证的生图效果：

| 候选 | 适合的识别依据 | 取舍 |
|---|---|---|
| Michael Jackson | 固定一场/一个时期的黑礼帽、单只亮片手套与舞步轮廓 | 适合先试不靠脸的识别；不同巡演不要混衣装；静帧拍舞步瞬间，不要求一张表现整段月球漫步 |

## 写卡与编译

`concert_audience` 的五张都写 `performance.act`（同一演出者与已选版本）和 `performance.visible`。入镜时另写 `description`，只包含本镜实际可见的舞台造型、乐器、站位、动作与画风；不入镜时可省略该描述，编译器不会把它带进提示词。

```json
"performance": {
  "act": "Queen，1986 Wembley 主题",
  "visible": true,
  "description": "远处舞台上的 Freddie 穿黄色短夹克和白裤，举起话筒杆；吉他、贝斯和鼓组分布在各自站位，人物面部细节不可辨"
}
```

乐队作为一个演出整体描述，不占“两位陪同角色”的卡片名额，也不需要给每名乐手建角色卡。舞台表演者若采用动画，在 `visual.characters` 明确选择；本人和环境照常分别选择。

当前两个玩法不组合台下陪同角色；遇到“和悟空一起去听”这类请求保留完整意图，说明组合尚未接入，并提出可评审的方案，不偷偷删掉伙伴。`my_stage` 不填写 `performance`，因为演出者就是本人。

## 画面与交付边界

- 舞台表演者只作远景表演，用服装、乐器、动作辨识，脸部细节不可辨；不安排近距离明星合照、后台会面、拥抱或握手。它是本玩法的范围，不是所有公众人物图像都被法律或平台禁止。
- 大屏只放抽象色块与灯光，不用歌手巨幅脸、姓名字幕或巡演标志补识别。观众与工作人员为不露脸的背景群像；演出者可以较亮，本人脸部仍需保留自然肤色与可辨五官。
- 乐器支架、麦克风、应援棒写清归属与持握；我的舞台保留明确选择的张嘴、转头和爆发动作，再检查本人感，不能自动收成闭嘴浅笑。乐队远景优先检查人数、乐器和肢体关系。
- 原有姓名扫描仍检查造型描述；如命中现有演员名词表，说明当前工具限制，不隐名绕过、不冒充法律判断。平台实际拒绝仍按主流程停止处理。
- 交付说明标为 AI 想象的舞台/观演故事；保留原图 AI 标识，不写成真实出席证明、官方合作或本人代言。程序检查不等于艺人识别和用户验收。
