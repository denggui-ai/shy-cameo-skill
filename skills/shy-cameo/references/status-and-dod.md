# 状态与完成标准

## 项目与系列

project-status从现有套图账本与选用版sidecar推导状态，不在project.json保存另一份完成标志。原版自动关联，重拍按索引候选关联；未选用新版不替换旧版验收。单套五张匹配交付且accepted才complete。本次selection所有套图complete才表示本次范围完成，不表示所有提案或未来系列完成。引用缺失/结果不一致为待整理；claimed不等于失败，也不自动恢复；generate-set遇结果未知时该张保持claimed、本次不再提交，核对后set-record，再--resume只拍未提交的张。套图账本缺失但已有首图文件或属于该套的request时，compile-shot、generate-set、set-status返回`ledger_missing`并停止，不按未开始重拍，也不自动重建为pending；先核对历史。格式与暂停规则见series-projects.md。

## 状态词表
| 对象 | 状态 | 含义 |
|---|---|---|
| 分镜卡 | `unverified` | 草稿 / 候选：模型现场生成，未经用户确认 |
| 分镜卡 | `user_confirmed` | 用户已确认，可以编译 |
| 分镜卡 | `gold` | 金牌场景：经过真实出图验证，随 skill 分发 |
| 角色卡 | `temp_draft` | 临时角色文字造型草稿 |
| 角色卡 | `temp_confirmed` | 用户已确认文字造型或定妆表（若制作） |
| 角色卡 | `gold` | 金牌角色：已由维护者提升并随库分发；具体质量验证范围另列，状态本身不是法律或质量证明 |
| 单图审计 | `pass` | 证据显示生图调用由本次 request.json 加载 |
| 单图审计 | `unverified` | 无法核对（常见，能力限制），可交付但须告知 |
| 单图审计 | `tampered` | 证据显示请求被改动或混入演员名，不建议公开发布 |
| 单图判定 | `pending` / `accepted` / `rejected` | 用户自检前 / 接受 / 拒绝（任一项回答“否”，含 --goal no，即 rejected） |
| 结果未知 | `failed_timeout` / `failed_no_image` | 超时 / 没拿到图，额度可能已扣，不自动重试；generate-set 中该张保持 claimed 并暂停，核对后才登记 |
| 首图待比脸 | `set_paused_likeness` | 露脸封面已生成并登记，机器比脸分低于阈值；后 4 张未提交，等用户比脸：像就 `--resume`，不像就改卡另起一套。机器分只是提醒，不等于“不像”，也不能当验收 |
| 阻断 | `blocked_consent` / `blocked_quota` / `blocked_name` / `blocked_platform_input` | 授权未确认 / 额度未授权或用完 / 演员名无法映射 / 平台拒绝 |

动画主题的离线编译通过不等于实际套图生成就绪或成片验收。`user_confirmed` 仅记录对相应分镜的确认，不能代替角色设计确认、成年人照片同意或本次生成意图。静态兼容测试使用合成夹具；实际候选卡不因此改为确认状态。

只有 `verdict: accepted` 的图才是最终交付；临时定妆表和未自检的出图都只是候选。
`verdict` 由 `CLI record-verdict` 按用户自检的回答写入 sidecar（本人感、角色、异常三项必填，本次目标 --goal 可选），模型不得自行改写；用户没答到的项要问，不替用户填“没问题”。

## Definition of Done（单张重拍或局部编辑）
适用于一套 5 张之外、对其中某一张重新授权 1 次的重拍或局部编辑；整套的完成标准见下方“套图（v4）”，两者都以 `verdict: accepted` 为准。`compile-edit` 仅写请求及参考摘要，不表示已提交、已交付或效果通过。
- 输入：`user_confirmed` 分镜卡及授权确认三项；普通重拍需`gold`或`temp_confirmed`角色卡及至少1张用户照片，局部编辑需已登记同意的指定底图和明确修改说明。
- 产物：`WS/outputs/<run_id>/request.json`、原图副本 `image.*`、`sidecar.json`；可选 `image-badge.png`。
- QA：photo-check、frame-check、verify 都已运行；用户完成三项自检。
- 不得声称：没有用户自检就说“完成”；`audit: unverified` 时说“已核验”；把静态检查或 pytest 通过说成真实出图验证。

## 套图（v4）
| 对象 | 状态 | 含义 |
|---|---|---|
| 套图卡 | `unverified` / `user_confirmed` | 5 张分镜未确认 / 已确认 |
| 账本单张 | `pending` / `claimed` | 未提交 / 已编译待生成 |
| 账本单张 | `generated` / `rejected` / `failed` | 成功 / 平台拒绝 / 核对后确认失败（都计额度）；未核对的超时或无图保持 `claimed` |
| 账本单张 | `cancelled` | 第 1 张失败后取消，未提交、不计额度 |

**Definition of Done（一套）**：
- 5 张都完成 deliver 与用户自检，且 `verdict: accepted`；
- 有失败或取消时，如实报告 `quota_used` 与每张的状态；
- 不得把部分完成说成完成。

## 出图后模型目视清单（交给用户自检前先过一遍，来自 POC 教训）
1. 角色有没有露脸：正面朝向的人形、镜中正脸或剪影、脸部黑影都算不合格。
   同时检查角色存在感与主次关系：实际入镜的体态、毛色、服饰或物件是否足以支持所选角色，是否因贴近镜头占成巨大前景或为凑特征而突兀裁头；主角是否仍是视觉中心。两人的位置、视线与接触动作是否回应同一事件，背影角色是否实际参与。只出现无法辨认身份的普通手掌时，应如实标记辨识不足；不能只因不露脸或角色更大就判合格。用户明确选择极少入镜的细节镜头按其目标检查，不自动扩大角色或重拍。
2. 人体与动作：头颈、肩背、上臂、肘腕、手指是否合理连接；衣袖与包带是否掩盖断肢、重复肢体或错误交叉；躯干朝向、脸朝向、视线和交接动作是否相容。逐张放大原图看，不只看联系表缩略图：上身与胯、腿是否同一朝向（背影常被画成腿朝前），露脸张头转是否超过约 20°、眼睛是否斜着看（D32）。
3. 道具：按 prop-direction.md 对照选物依据与人物身份、地点时代、用户指定的反差；比较物件与衣装、伙伴、环境的色彩反光和体量，确认主体与视觉焦点。跨图核对关键物件数量、归属、开合、消耗或明确修改，出框不等于丢失，重复出现不自动算重复构图。再检查实际物件、使用状态与已定活动是否一致，是否无故新增故事或抢过人物互动；再核对颜色、材质、长短与 `prop_specs`。按设计检查握持、搭放或桌面支撑，不要求所有道具入手；远景道具有没有失真发假。沿身体—上臂—前臂—手—道具检查前后、遮挡、接触和支撑是否一致，如演奏是否像反手绕到背后、手是否穿过器物。再检查可见结构与使用状态是否自洽，如摊开本子的书脊、两侧页块与封面是否连贯，手势是否误读成缺工具的操作。裁切或遮挡导致看不清时标为关系不清，不能直接断言画反，也不能仅凭道具名称判正确。结构画对不等于道具选对；局部编辑前后都检查，身份改善不能替代空间关系通过。
4. 空间与节拍是否符合已确认的玩法计划：本次实际确认的动作与节奏；首尾可复用，同景例外须已明确确认。指令是否照做：色调（黑白不是棕褐）、时辰（黎明不是夕阳）、人物性别、左右站位。
5. 多余元素：卡通图案混进戏服、时代不符的地标、`frame-check` 报 `extra_faces` 时有没有多出路人。
6. 主角的脸有没有被画得像某位真实演员（妆造往公认形象靠时尤其要看）；像就如实说明、不建议发布。
7. 用户要求真实机位时：逐张对照已记录的实景来源，检查地标、桥梁、岸线、台阶与遮挡关系；无法对应时标为机位未验证，不以城市名或地标名代替核实。
8. 造型修改同时检查三件事：仍可辨为本人、明确要求的变化可见成立、本次保留项没有明显附带漂移。收腰看不出变化不能因脸保留就判通过；换裙子却改了未授权的妆发需记录缺陷。遮挡或出框的身形、裙长、鞋款记未观察，材质外观不证明真实纤维。生成成功、模型目视通过与用户接受分别记录；平台拒绝或缺图不能算整套通过，不为补齐改词绕过拒绝。
发现问题如实告诉用户，区分已确认的画面缺陷与尚未查明的原因；不能直接归咎编译器，也不能把调用成功当画质通过。不自动重拍；用户明确指定重拍时才开始新任务。

开发案例集可分为待验收候选、用户已验收、问题与改进、历史案例。每组保留玩法、分镜、实际输出、检查结果和经验；成功展示以实际验收范围为准。案例页的编辑状态不能替代CLI的用户verdict；用户要求本地整理不等于远端发布。

`set_generated` 仅表示五张均生成，仍待 deliver 与用户验收；不是套图完成。CLI 接受最终 accepted 前要求本次审计、图片构图记录及交付摘要齐全且匹配；audit 可为已告知的 unverified；audit 为 tampered 时 record-verdict 拒绝正式 accepted（`audit_tampered`），sidecar 与 audit.json 原样保留为问题证据，仍可记 rejected，project-status 也不把此类接受计为完成。

## 摄影与输出来源

检查用户所选电影感/舞台/旅行/动画效果是否体现在镜头目的、光源、前中后景、动作、色彩与连续性中；具体见routing-and-journey.md。没有新图验证时只能说摄影方案与编译已验证，不宣称画质已修好。人体、真实机位和风格仍需目视核对。

PNG像素流检查与人脸检测分开；检测器缺失不放行坏PNG。audit pass限调用窗口参数与次数；图片/请求分别绑定哈希不等于图像服务输出来源已自动证明。CLI异常退出或旧图片路径不作为成功；保留结果待核查，不自动重试。当前原生输出关联仍需核对实际工具返回路径，未验证时如实标记。

## 本人感与素材覆盖

按 photo-guide/README.md 分别记录实际姿态、本人感绝对评价和组内相对偏好。助手认为更像、文件完整性通过、或用户只选相对较好的一张，都不能替代本人感通过；范围结论附输入包与样本条件，不外推为通用角度限制。私有研究记录不自动改写CLI verdict或已接受的旧版本。
